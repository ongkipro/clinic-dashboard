## Design (proposed)

**Keys (first runtime use of DATA-8; needs the plan review):**
- Table `tenant_data_keys` (platform):
  - columns: tenant, version, the wrapped DEK, created_at, current flag;
  - one current row per tenant;
  - no grant to `clinic_app`.

  A definer `tenant_data_keys_for(tenant)` returns the wrapped DEKs of the caller's own tenant only. They are useless without the KEK, which never touches the database.
- The DEK is created lazily, at a tenant's first encrypted write, by `tenant_data_key_ensure(wrapped)`. The wrap happens in the app with the KEK; the database inserts version 1 only if the tenant has no DEK yet, and a race ends with one row.
- The app loads the KEK ring once per process from `KEK_FILE`. Without it, registration with an identity number is refused (`ERR_UNAVAILABLE`, "Kunci enkripsi belum dipasang"); it never falls back to clear text.
- Tests and the browser check use a throwaway KEK file written at 0400 in a temp directory.

**Data** (migration 0058, renumbered at integration per DEC-049):
- `patients`:
  - `mrn`, generated per tenant: `RM-` + a gap-free sequence through a per-tenant counter row locked in the writer;
  - `full_name`, `birth_date`, `sex`;
  - `identity_type` (nik / passport / kitas / newborn_via_guardian);
  - `identity_enc`, `identity_bidx`, with UNIQUE (tenant, identity_bidx) where not null;
  - `no_identity_reason`, required for newborn_via_guardian;
  - `religion`, `occupation`, `education`, `marital_status`: required, from closed lists with "lainnya";
  - `address`, `registered_branch_id`, `created_by`, `created_at`.

  Never deleted (guard).
- `contact_points`: patient, kind (phone; email later), the normalised value (E.164 `+62…`), primary. Not unique across patients (PR-5).
- `guardians`: patient, guardian name, relation, phone, optional `guardian_patient_id`. Required when the patient is a minor under 18 on the registration date, and for `newborn_via_guardian`.
- No `ihs_patient_id` write yet; SATUSEHAT is a later milestone.

**Writes** (SECURITY DEFINER under `tenant_actor_lock`, audited, event `PatientRegistered` with ids only): `patient_register(fields, identity_enc, identity_bidx, decision)`.
- Roles: FO/cashier and central CS (UX-4). Owner, Admin Pusat and manager too, per the 07 identity column; needs the plan review.
- The app encrypts and indexes before the call; the database never sees the NIK in clear.
- A NIK is 16 digits (format check only; no checksum is claimed).
- Duplicates:
  - The same identity index in the tenant is refused with `ERR_DUPLICATE` and returns the existing patient's id for an explicit choice.
  - The same phone, or the same name and date of birth, does not block. The writer requires `decision = 'new'` when matches exist; the screen first shows the matches with name, MRN, masked phone and year of birth only (PR-76 projection), and the user picks "Pilih" or "Buat Baru".

**Readers:**
- `patient_matches(phone_or_name_dob)`: a definer returning the minimal projection for FO and CS.
- RLS on `patients` for the identity roles in 07.

The clinical data that PR-5 says must never be exposed belongs to later tasks. T-037 has no clinical columns, so "neither record shows the other's clinical data" holds by construction, and a test pins the projection.

**PR-1 audit of a cross-tenant attempt:** `patient_get(id)` is a definer that returns the row, or not-found and an `audit_append(..., 'denied', 'patient_not_found')` row when the id is not the caller's tenant's. That covers "an audit event records the attempt". Needs the plan review: should the event be written for every not-found, which then also covers an honest typo?

**UI:** `/pasien/baru`:
- "Cari dulu" by phone, name, No. RM or NIK. The NIK is searched through the blind index and never sent back.
- The form has the identity sections (Permenkes fields), the guardian section shown for minors, and a Persetujuan placeholder: consents are T-038, so the section says the consent step follows.
- The duplicate step lists the matches, with Pilih or Buat Baru.
- After save, the patient's MRN is shown, with links to booking (T-044) and visit (T-047) once those exist.

**Vendor support class:** `patients`, `contact_points` and `guardians` are `personal` (Owner approval first); `tenant_data_keys` is platform, not readable by operators.

## Plan review round 1 (Argon; GPT-6.1 Sol 429): REVISE PLAN → adopted

The open points are resolved as the reviewer recommended:
1. `tenant_data_keys` is a platform table (RLS on, no grants), created lazily. `tenant_data_key_ensure(wrapped)` inserts version 1 with ON CONFLICT DO NOTHING and **returns the stored winning row**; the app encrypts and indexes only with that returned DEK. A search before any DEK exists returns no match and creates nothing.
2. Only `fo_cashier` and `central_cs` register (UX-4 17:165, 19:53, nav `/pasien/baru` "FO CS"). The other 07 identity roles read.
3. The MRN is `RM-` plus a zero-padded six-digit gap-free per-tenant sequence (`patient_mrn_counters`, platform, no grants). The writer increments it after every check, so a refused registration consumes no number (19:330/340, class F).
4. `patient_get(id)` audits **every** not-found in the caller's own chain (`access_denied`, `patient_not_found`) and returns null without raising, so the audit row commits. A cross-tenant id and an unknown id are indistinguishable (TEN-1, TD-51).
5. A minor is under 18 on the registration date in the registration branch's timezone (UU 35/2014 Pasal 1 angka 1; Q-07 confirms). A guardian is required for a minor and for `newborn_via_guardian`, and optional for adults.

Defects adopted:
- **P1-1:** `patient_register` audits `settings_change` / `patient_registered`. `patient_get` checks the actor with `tenant_actor_lock` and the 07 reader roles; a role outside them is audited `access_denied` / `role_forbidden`. The TS caller commits before answering not-found.
- **P1-2:** identity rules in TS and as table checks:
  - `nik`: 16 digits;
  - `passport` / `kitas`: normalised `^[A-Z0-9-]{4,30}$` plus a no-NIK reason of 3–300 characters;
  - `newborn_via_guardian`: no number, a reason, and a guardian.

  `identity_enc` must match the `v1.` format and `identity_bidx` 43 base64url characters. The index input is `<type>:<normalised>` under purpose `patient.identity`.

  The duplicate step never echoes the number. The action returns the sealed `identity_enc` / `identity_bidx` and a masked display (`••••••••••••8901`) as hidden fields for "Buat Baru". The input has `autoComplete="off"`. The number never appears in state, URLs, logs, events or errors.
- **P1-3:** the base RLS on `patients`, `contact_points` and `guardians` admits the 13 non-marketing identity roles (owner, admin_pusat, manager, facility_head, records_officer, fo_cashier, central_cs, bc, doctor, nurse, therapist, pharmacist, finance). Marketing gets its consent-filtered view with T-038 (TEN-18). `clinic_app` gets a column grant on `patients` without `identity_enc` and `identity_bidx` (as `staff_invitations.token_hash`, DEC-024).
- **P1-4:** `patient_register` requires `tenant_capability('new_booking')`, which is live only. A suspended tenant takes no new business (PR-56), and onboarding / provisioning hold no patients (TEN-12). The existing capability function is used rather than a new state list. The TS wrapper calls `assertProductionGoLive` (ARCH-10, PR-36, DEC-018).
- **P1-5:** the 05 §3.1 contract applies to every table: `UNIQUE (tenant_id, id)`, composite RESTRICT FKs, and the guardian link composite with `guardian_patient_id <> patient_id`. The branch is `coalesce(active branch, chosen branch)`; another branch than the active one is refused, and central CS on "Semua Cabang" picks one. The registration date and age come from that branch's timezone. `ihs_patient_id` stays null, and `created_as` is added.
- **P2-1:** `patient_register` returns jsonb:
  - `duplicate_identity` with the existing match, offering Pilih only;
  - `duplicate_decision_required` with the matches (phone, or name + date of birth), showing the UX-4 copy with Pilih / Buat Baru;
  - `ok` with `patient_id` and `mrn`.

  `patient_matches(phone, name, dob, mrn, identity_bidx)` covers the four 19:53 search modes, returns at most 20 rows of `id, mrn, full_name, birth_year, masked_phone`, and is open to FO and CS only. Phones are normalised the same way in SQL and TS: `08…` / `628…` become `+628…`, then checked against `^\+[1-9][0-9]{7,14}$`.
- **P2-2:** scope expansions: `tests/rls/rls.test.ts`, `tests/rls/authority-clock.test.ts`, `tests/isolation/cases/pasien-baru.cases.ts`, `tests/context/stale-context.test.ts`, `tests/ui/pasien-baru.spec.ts`. Drift lives under `tests/patients/`, so it needs no expansion. The keys loader (`src/lib/keys/runtime.ts`, KEK once per process from `KEK_FILE`) is a further expansion, because `src/lib/keys/**` is outside the paths.
- **P3-1:** added tests:
  - the DEK race (both callers get the winner, and both values decrypt);
