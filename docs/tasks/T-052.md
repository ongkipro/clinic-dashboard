## Design (proposed, for plan review)

**Split with later tasks.** T-052 builds the draft examination and the plan; T-053 signs, locks and corrects (PR-13); T-054 consent and start gates; T-055 photos; prescriptions and Kirim ke Kasir later (M3/M4). The sheet shows those parts as later states, not dead buttons.

**Data** (migration 0070, `src/modules/clinical/schema.ts`):
- `intake_verifications` (CLIN-004): per intake fact (or per reviewed prior fact) the doctor's decision `confirmed` | `corrected` with a corrected value, verifier, time; the BC fact row is never changed (author kept).
- `examinations`: one draft per visit (doctor author), SOAP sections (subjective, objective, assessment text, plan note), template key + structured values (jsonb validated per template: Fitzpatrick I–VI and scales are allowed here — doctor-only), vital signs, ICD-10 codes (closed list later; text code for now?), state `draft` (signing in T-053).
- `face_map_marks`: examination, layer (`keluhan`, `pemeriksaan`, `tindakan`), template (face front / left / right / body), x, y (0–1 normalized), label, product/catalog version (tindakan), dose + unit per point (integer micro-units; no float).
- `care_plans` (CLIN-012): patient, title, condition, state (active / completed / stopped), created by doctor; several in parallel. `plan_items`: plan, stage (1..n), catalog_version, qty, unit, dose per item, note; price is read live from the branch price (preview) — no money is stored here (M4 freezes prices on the invoice).
- RLS: examinations, marks, plans readable by doctor, facility head, records officer (clinical); BC and FO through a definer projection `plan_options(visit)` returning items, stages and prices only — no assessment, diagnosis, dose or rationale (07:45; Done-when "BC projection shows items and prices only").

**Writers** (definer, `tenant_actor_lock` first, doctor at the visit's branch, capability `existing_appointment`, draft only, idempotent, audited, ids-only events): `exam_open(visit)` (visits.doctor → in_progress), `exam_save(exam, payload)` (allowlist, template validation), `intake_verify(exam, fact, decision, value?)`, `mark_set` / `mark_remove`, `plan_create`, `plan_item_upsert`, `plan_close`.

**Readers:** `exam_sheet(visit)` (doctor: patient header, cautions, today's intake with verification state, the patient's earlier visits with their intakes/exams, active plans — PR-10 one screen; audited clinical read), `plan_options(visit)` (BC/FO projection).

**UI** (`/pemeriksaan`, `/pemeriksaan/[visitId]`): doctor's queue (visits at the branch with intake done), the sheet in panes per UX-8, intake rows with Benar / Koreksi, SOAP with a template picker, face map (SVG, three layers, tap to place, dose per point, accessible table of marks), staged plan editor with live prices; "Tanda Tangani" shown disabled with the reason (T-053).
