## Open points (for the reviewer)

1. **Item master.** Proposal: `stock_items` one per catalog item of kind `material` or `product` (FK, unique), carrying the stock attributes the catalog lacks: use `unit` (e.g. `ml`, `U`, `pcs`), `vial_size` and `opened_use_hours` (both or neither: a vial item; CD-20), `storage` (`ruang` | `sejuk` | `dingin`), `registration_no` (BPOM/KFA, optional), `high_value` (CD-22 count class), `active`. Name and code come from the catalog. Writers: pharmacist, purchasing, admin pusat (nav "PH PU AP").
2. **How stock enters before T-067.** Goods receipt is T-067. Proposal: `stock_receive` writes a batch (or adds to an existing batch of the same item, number and expiry at the branch) with a `receive` movement and a reason (`stok_awal` | `penerimaan`); T-067's goods receipt calls the same internal function. Expiry is required (UX-52 copy "Batch tanpa tanggal kedaluwarsa tidak dapat diterima"); an expired date is refused. Pharmacist, purchasing.
3. **Branch quantity now, depots in T-061.** Proposal: `stock_batches.quantity` is the branch quantity here; T-061 adds `depots`/`batch_holdings` and moves each batch's quantity into the branch's default gudang. This task names that hand-over in ARCHITECTURE/STATUS and does not pre-build depots.
4. **Opened vials.** Proposal: `opened_vials` (batch, opened_at, use_by = opened_at + item.opened_use_hours, `remaining` in use units, state `open` | `finished` | `lapsed`). Opening does not move stock (the units stay in the batch; the vial row says which part is open). Only vial items; one open vial per batch at a time; opening refused when the batch is unfit. A lapsed vial's remainder is unfit (wasted by T-062). Pharmacist (nurse and the room come with T-062/T-064). Extending use-by (CD-20, two people) is not built: no request in this task's acceptance; recorded as open.
5. **Fitness and FEFO (CLIN-019).** Proposal: one definer `stock_unfit_reason(batch)` → `expired` | `recalled` | `quarantined` | `vial_lapsed` | null, judged on the wall clock in the branch's time zone (expiry is a date: unfit from the start of that day). `stock_fefo(item, qty)` returns the batches to take, open vial within use-by first, then fit batches by expiry then received time, never an unfit one; `ERR_STOCK_INSUFFICIENT` when fit stock is short. `stock_assert_fit(batch, qty)` raises `ERR_STOCK_UNFIT` / `ERR_STOCK_INSUFFICIENT`: what T-062/T-065 call before issuing or dispensing. Batch state `active` | `quarantined` | `recalled` set by `stock_batch_hold(batch, state, reason)` (pharmacist; recalled is final).
6. **Min/target (SET-26).** Proposal: `stock_levels` (branch, item, min ≥ 0, target ≥ min) set by pharmacist or purchasing at their branch (purchasing is tenant-wide and names the branch); `stock_low` reader lists items whose fit quantity is below min. Not a `setting_versions` row (SET-26 is `ref`, href `/stok`).
7. **Counts and adjustment (PR-44).** Proposal: `stock_counts` (branch, blind, state `draft` | `submitted` | `pending_approval` | `applied` | `rejected` | `cancelled`) with `stock_count_lines` (batch, system qty snapshot at start, counted qty). Blind: the counter's reader hides the system quantity until submitted. Submit: if every line's |counted − system| ≤ SET-43 `selisih_opname` % of system (system 0 with counted ≠ 0 always exceeds), the adjustments apply at once; otherwise one approval `stock_adjustment` (subject `stock_count`, reason = the count reason, branch) and an `approvals` AFTER UPDATE trigger applies on approve / marks rejected or cancelled (as `record_correction_sync`). Applying writes one `adjust` movement per line with a difference, against the system snapshot **and** refuses (fails closed) when the batch moved since the snapshot. Who: pharmacist and manager count; approvers per the type (owner, manager; never the requester). Purchasing may request the type but does not count here (nav "PH M").
8. **Readers and roles.** Proposal: read `stock_items`, batches, vials, levels, movements, counts: owner, admin pusat, finance, purchasing, auditor (tenant-wide, every branch) and manager, pharmacist (their branches). Nurse and therapist read later with the room (T-064). No patient or clinical data in these tables (T-060 movements are receive/adjust only), so purchasing and auditor see them whole; the masking of patient-linked rows (IAM-12) applies when consumption arrives (T-062). Support class `config` for items, levels; `money_total`? no — `personal`? none of these hold persons; proposal `config` for all stock tables (no patient, no clinical content).

- `stock_batches` (tenant, branch, item, batch_no, expiry date, quantity numeric ≥ 0, state, hold_reason, received_at; unique (tenant, branch, item, batch_no, expiry)).

### Findings adopted
- **P1-1** as open points 4–5.
- **P1-2** batch ↔ movement both ways in one transaction: a constraint trigger (`DEFERRABLE INITIALLY IMMEDIATE`, re-checked at commit) on `stock_batches` and on `stock_movements`: for each touched batch, the quantity change equals the sum of the movements inserted for it in the current transaction, the newest movement's `balance_after` equals the quantity, and no movement is inserted without its batch change. Unit freeze as open point 1. Every numeric column bounded with `BETWEEN` and `scale(...) <= 4` (rejects `NaN`/`Infinity`). `stock_batches` unique `(tenant, branch, id)` and `(tenant, branch, item, id)`; `stock_counts` unique `(tenant, branch, id)`; FKs from vials, movements and count lines bind `(tenant, branch, …)` (movements also the item).
- **P1-3** as open point 7; movement idempotency: unique `(tenant, source_kind, source_id, batch_id)` (receive: the command id; adjust: the count id); TS writers use `runCommand` after `assertProductionGoLive`; `ERR_STOCK_UNFIT` / `ERR_STOCK_INSUFFICIENT` are stored domain refusals.
- **P2-1** stock readers resolve catalog name/code/kind in definers (as `catalog_commercial()`), never by an invoker join; support classes and scope map as open point 8; the Kartu Stok reader already masks `reason` and `source_id` for purchasing and auditor on patient-linked kinds (`issue`, `consume`, `return`, `waste`), for T-062/T-065.

## Plan review round 2 (Argon `5bff07a3`): APPROVE PLAN

Report `/data/tmp/clinic-dashboard/t060/plan-r2-argon-5bff07a3.md`. Implementation notes adopted:
- **P3-1** the two-way check: each `stock_batches` row change must match one movement of the current transaction (`xmin = pg_current_xact_id()`, `quantity = NEW − OLD`, `balance_after = NEW`); each movement must match a batch change of the transaction, and the batch's movements in the transaction form a contiguous chain ending at the batch quantity.
