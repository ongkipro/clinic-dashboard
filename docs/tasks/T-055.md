## Design (proposed)

**Storage choice (open point 1):** bytes in the database now behind a `MediaStore` interface in `src/modules/clinical/media/store.ts` (`put`, `get` by content address), implementation `DbMediaStore` over `clinical_media_blobs`; the S3 adapter later swaps in by configuration (ARCH-9) without changing callers. Recommend this (matches DEC-027; no bucket or credentials needed for M2; tests run fully local).

**Data** (migration 0072):
- `clinical_media` (tenant, branch, patient, visit, examination nullable, kind `photo` | `document`, angle (SET-29 enum, photos), taken_at, content_type (jpeg/png/pdf from the bytes), size_bytes ≤ 10 MB?, sha256, width/height for photos (from the bytes; comparability), uploaded_by/as, created_at, `removed_at` + reason (never deleted; a mistaken upload is hidden, not erased). Blob in `clinical_media_blobs` (tenant, sha256, content bytea; CHECK sha256 = digest; dedup per tenant).
- `media_tokens` (tenant, media, staff, session id?, token hash (sha256 of a random 32-byte token; the token itself is shown once), purpose `view` | `download`, issued_at, expires_at ≤ issued + 10 min (CHECK), used_count). The token is bound to the issuing staff and acting role.
- RLS: clinical class; readers through an invoker wall-clock helper: doctor, nurse, therapist, facility head, records officer, BC (photos only — BC captures photos in UX-7; open point 3) at the branch; non-clinical roles (FO, cashier, finance, marketing, owner as owner) none (CLIN-021).
- **Assignment (CLIN-026, open point 2):** there is no visit-assignment model yet (per-visit BC/doctor assignment is M3). Recommend: "assignment" = an active staff_branches row for the acting clinical role at the media's branch on the wall clock (the same rule as `exam_readable`); losing the branch role or the membership removes access immediately, including for already issued tokens (the token check re-evaluates the reader rule at use time).

**Writers / readers** (definer; actor lock first):
- `media_add(visit, kind, angle, bytes…)` from TS: TS validates the type from the bytes and computes width/height (PNG/JPEG headers, no dependency), the database checks sha256 and size; BC or doctor or nurse at the visit's branch; open visit; audited `media_upload`? (audit action list: 'media_view','media_download' exist; upload → 'settings_change'? open point 5).
- `media_token_issue(media, purpose)` → returns the raw token once; stores the hash; ≤ 10 min (default 5); audited.
- `media_token_redeem(token)` → returns content type, bytes (through the store), filename; refuses expired (PR-32 scenario: "older than its lifetime"), wrong staff, revoked access (wall clock), removed media; audited `media_view` / `media_download`.
- `media_list(patient | visit)` (clinical readers; merge cluster): metadata only (no bytes, no tokens).
- `media_compare(a, b)` (CLIN-015): returns both metadata and a comparability verdict: same angle, same kind, dimensions/aspect within tolerance, taken ≥ 1 day apart → comparable; else `warning` with reasons (`angle_differs`, `aspect_differs`, …); never a score or improvement percentage (CLIN-013).
- `media_remove(media, reason)`: uploader or facility head; hides, never deletes.

**Module** `src/modules/clinical/media/{media.ts,store.ts,image.ts}`; route handler for token redemption is UI work (later) — the module exposes `redeem(token)` returning bytes and headers.

**Scope expansions** (expected): `tests/rls/rls.test.ts`, `tests/rls/authority-clock.test.ts`; `next.config` body limit if uploads exceed 6 MB (avoid: cap at 5 MB like DEC-027).

## Plan review round 1 (Argon `6074b48f`): REVISE PLAN → adopted

Open points decided: (1) bytes in `clinical_media_blobs` behind `MediaStore` (`store.ts`), content-addressed, object key `tenants/<tenant>/clinical-media/<sha256>` (TEN-4), DB now (DEC-027), S3 by configuration later (ARCH-9). (2) "Assignment" = membership + `staff_branches` row for the acting role at the media's branch on the wall clock (`media_readable`), re-checked by list, compare, issue and redeem. (3) Readers: doctor, nurse, therapist, facility head, records officer read photos and documents at their branch; BC captures and reads photos only; pharmacist and every non-clinical role read nothing. (4) Tokens: default 300 s, max 600 s (CHECK), multi-use within the lifetime, bound to tenant, staff and acting role; access and removal re-checked at each use. (5) Audit: `settings_change` (`media_uploaded`, `media_removed`); `clinical_read` (`media_token_issued`, `media_listed`, `media_compared`); `media_view` / `media_download` at redemption; never a free-text audit reason. (6) Cap 5 MB. (7) No export or publication here; token purposes `view` | `download` only.

Findings adopted:
- **P1-1 contract:** `clinical_media_blobs` (id, tenant, sha256, content_type, size_bytes, content, created_at; unique (tenant, id), unique (tenant, sha256); sha256 = digest CHECK); `clinical_media` carries `sha256` and `object_key` without an FK to blobs (store swap needs no DDL). Scope map + support classes: `clinical_media` clinical (operator read), `clinical_media_blobs` and `media_tokens` class `never`, RLS on, no grant or policy for app or operator. `DbMediaStore` only through definers `media_blob_put` (actor lock, uploader roles, capability, size, magic bytes, sha256) and `media_blob_get(token_hash)` (a live redeemed token of the caller, media readable now, not removed).
- **P1-2 tokens:** the raw 32-byte token is made in TS (base64url) and only its sha256 reaches SQL (`media_token_issue(media, purpose, token_hash, ttl_seconds)`); idempotency results hold `{token_id, expires_at}` only. `media_tokens` (tenant, branch, media, staff, acting_role, token_hash unique, purpose, issued_at, expires_at, used_count, last_used_at; CHECKs as reviewed). `media_token_redeem(token_hash)`: actor lock, clinical role, capability `clinical_read`, token of this tenant, staff and role, `clock_timestamp() <= expires_at`, not removed, readable now; increments use; audited `media_view` / `media_download`. `media_list`: clinical role check first (CLIN-021 → ERR_FORBIDDEN), capability, then rows filtered by `media_readable` (CLIN-026 → empty).
- **P1-3 validation and guards:** `clinical_media` adds `file_name`, `object_key`, `removed_by/as/at/reason` with the reviewed CHECKs (kind ⇔ type, photo ⇔ angle and dimensions, SET-29 angles, size, object key, file name, BC photos only, removal all-or-none). Type and dimensions from the bytes in `image.ts` (PDF, PNG IHDR, JPEG SOF scan; corrupt headers refused). An examination link must be the visit's draft; removal is refused when the linked examination is signed. Guards on all three tables (staff_access first, ENABLE ALWAYS, no truncate): media never deleted, identity immutable, removal once; blobs insert-only; tokens only increment use.
- **P2-1 compare:** two different photos of the same canonical patient, readable, not removed; integer rules: `angle_differs`, `angle_not_in_protocol` (SET-29 now), `aspect_differs` (> 5 % by cross-multiplication), `time_too_close` (< 24 h); returns status, reasons, earlier, later; never a score or percentage; audited.
- **P2-2:** audit reasons NULL (free text only in `removed_reason`); events `ClinicalMediaAdded` / `ClinicalMediaRemoved` with ids and lower-case codes; `runCommand` body has metadata and sha256, never bytes; result `{media_id, sha256, object_key}`.
- **P2-3:** scope expansions `tests/rls/rls.test.ts`, `tests/rls/authority-clock.test.ts` only.
