## Review

- **Finding — MEDIUM (P1): UTF-16 offsets applied to a code-point array can hide real DDL.**  
  **Location:** `tests/rls/harness-lock.test.ts:107–108`.

  TypeScript comment ranges use UTF-16 code-unit offsets, but `[...text]` creates an array of Unicode code points. Astral characters before a comment therefore shift the range being blanked.

  For example, this valid source should produce `["1"]`:

  ```ts
  const s = "😀😀"; await q(/* ignored */`CREATE DATABASE x`);
  ```

  The two emoji produce a two-position offset mismatch. Blanking the comment consequently also blanks the following opening backtick and the `C` in `CREATE`. The remaining `REATE DATABASE` does not match, so the scan misses the actual statement. Duplicate comment ranges do not correct this.

  **Concrete fix:** Change `const chars = [...text]` to `const chars = text.split("")`, preserving UTF-16 indexing. Add the example above as a regression, plus an astral-character fixture confirming that DDL inside a comment remains ignored.
