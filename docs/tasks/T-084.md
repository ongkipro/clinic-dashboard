## 4 Design

### 4.1 Tables (tenant-ledger; never deleted; guards take staff_access first; no-truncate ENABLE ALWAYS)
- **`expense_categories`** — `id, tenant_id, name` (unique per tenant, 2–60), `active`, created/updated by/at. Seeded per tenant on first use?
  → No seed: owner/finance create categories (open point 1). "category/account": the account code joins at M8 (column `account_code text
  NULL` reserved? → YAGNI: not added; M8 maps categories to accounts).
- **`expenses`** — `id, tenant_id, branch_id, category_id, business_date date` (branch-local, not in the future, back-dating limited by
  SET-41 `mundur`? → see open point 3), `amount bigint` (1..MONEY), `funding` `petty_cash|cash|bank|unpaid`, `description` (3–200),
  `supplier_id` (required when unpaid, optional otherwise), `receipt_*` (`receipt_file_name`, `receipt_media_type`, `receipt_size`,
  `receipt_sha256`, `receipt_content bytea`; **required for petty_cash and cash**, optional for bank/unpaid — open point 2), `state`
  `recorded|reversed`, `reversed_at/by/as`, `reverse_reason`, `command_key`, `recorded_by/as/at`. Content frozen; only the reversal columns
  change once.
- `supplier_invoices.expense_id` FK → `expenses (tenant_id, id)`.

### 4.2 Writers
- **`expense_record(p_key, p_branch, p jsonb)`** — finance (any branch) and manager (own branch) (`19:182`); owner too (Level 1 of the
  tenant, ◐ on stock/purchasing); `payables_actor(['owner','finance','manager'], p_branch)` (verify the owner is admissible through
  `stock_actor`). Validates the category (active, tenant), date, amount, funding, receipt (type/size/sha checked in SQL: sha256 of content =
  given hash), supplier for unpaid. Inserts the expense; **when unpaid, inserts in the same transaction one `supplier_invoices` row**
  (`kind = 'expense'`, `expense_id`, supplier, branch, number = the payee's invoice number from input or a generated `EXP-<short id>`,
  invoice date = business date, due date = + supplier terms, total = amount, no lines). Emits `ExpenseRecorded` (ids only). Audit.
  Idempotent by key.
- **`expense_reverse(p_key, p_expense, p_reason)`** — finance or owner; refused when its payable has any live allocation or credit
  (`ERR_VERSION_CONFLICT: expense_paid` — reverse the payment first); reverses the linked invoice in the same transaction (state `reversed`, as
  `supplier_payable_reverse` does at `0084:1251-1263`, but emitting only `ExpenseReversed`: the expense owns the AP, `11:124,134`).
  **`supplier_payable_reverse('invoice', …)` must refuse `kind = 'expense'`** (`ERR_VERSION_CONFLICT: expense_invoice` — reverse the
  expense instead), else an expense would keep a live record with its payable gone; re-created (§5). Correction = reverse + record anew.
- **`expense_category_save(p_key, p)`** — owner, finance; create or rename/deactivate (never delete).

### 4.3 Readers
- **`expenses_list(p_branch, p_from, p_to, p_category, p_funding)`** — finance, owner, auditor tenant-wide; manager own branch. Rows without
  receipt content (a flag and the file name); `expense_receipt(p_expense)` returns the file for the same readers.
- **`expense_branch_totals(p_from date, p_to date)`** — per branch and category, the sum of **recorded, not reversed** expenses with
  `business_date` in the period; the margin report (dashboards, later) consumes it. This is the scenario's "B1 margin includes it in that
  period". RLS on `expenses`: `stock_cost_readable(tenant, branch)` like the payables (Admin Pusat reads? → `stock_cost_readable` includes
  admin_pusat; acceptable for operational costs — open point 4).

- Detail: receipt preview, payable link (when unpaid), Batalkan (reverse) with reason for finance/owner.

## 5 SQL functions to re-create

- `supplier_payable_reverse(text,uuid,text)` (latest `0084:1238`): refuse an `expense` invoice (above).
- `supplier_invoices_guard` (`0084:549-573`): unchanged — it checks no lines and no kind (verified).
- **`supplier_invoices_total_check()`** (`0084:579-593`, DEFERRABLE constraint trigger, ENABLE ALWAYS): an invoice's `total` must equal
  the sum of its lines — **an expense invoice with no lines would fail at commit**. Re-created: for `kind = 'expense'` the total must equal
  the linked expense's `amount` (and the invoice has no lines); purchase invoices keep the line rule. (Chosen over inserting a synthetic
  line: `supplier_invoice_lines_guard` `0084:612` requires a receipt exactly for purchase invoices and refuses a receipt on an expense one,
  so a line would need a receipt-less shape the guard was written to forbid.)
- `supplier_invoice_lines` guard (`0084:612`: `(inv.kind = 'purchase') <> (NEW.receipt_id IS NOT NULL)`): an expense invoice has no lines
  (DATA-64 "matched … to one `expenses` row" = the `expense_id` link) — no change.
- Payment allocation: verified — neither `supplier_payment_record` nor `supplier_payment_allocate` (`0084:1051`, `:1085`) reads `kind`;
  an expense invoice is paid through the same flow (BILL-37 "never a second expense").
- Actor: `stock_actor` (`0077_stock.sql:225`, roles check `:260` includes owner) admits the owner; `payables_actor` requires a branch
  (tenant-wide roles name it).

## 6 Open points (recommendations; no [OWNER] point expected)

1. **Categories**: tenant-defined list (owner/finance), no seeded chart (accounts come with M8 / A-02 posting map).
2. **Receipt required**: for petty cash and cash (the scenario and "dengan bukti" `19:182`); optional for bank and unpaid (the payable has
   the supplier's invoice). Max 5 MB, PDF/PNG/JPEG (the evidence pattern).
3. **Back-dating**: business date ≤ today (branch-local); no lower bound beyond the open period (period locks are M8). SET-41 `mundur`
   concerns cashier transactions; not applied (no new setting).
4. **Readers**: `stock_cost_readable` set (owner, admin_pusat, finance, purchasing, auditor, branch manager). If Admin Pusat/purchasing
   should not read expenses, a dedicated predicate (owner, finance, auditor, branch manager) — recommend the dedicated predicate.
5. **Petty cash balance** (top-ups, float): not in PR-79/BILL-37 rows; T-085 Tutup Kasir covers cash drawer reconciliation. → Out of scope;
   petty cash is a funding label only.
