# HYG-012 — Vendor console access: allowlist switch, emergency command, optional passkeys

Status: PLANNED (owner decision DEC-042, 2026-11-05) · Risk: R3 (vendor authentication)

## Why

Office and home IP addresses are dynamic, so an enforced allowlist would lock the vendor team out. The owner decided (DEC-042):
- no enforced allowlist for now;
- the second factor stays mandatory;
- passkeys are optional but recommended.

The decision is revisable, so the allowlist must be switchable without code changes.

## Change (plan to write in full; validate each library claim against the official docs and the installed source first)

1. **Allowlist switch.** A platform setting `vendor_ip_enforced` (boolean, default false), in a platform table that `clinic_app` cannot reach.
   - `vendor_ip_allowed(ip)` returns true when it is false.
   - Turning it on or off is a platform-owner action with step-up, logged in the vendor log.
   - Turning it on refuses when the actor's own current address is not in the list, so nobody locks themselves out.
   - Tests cover both states. With enforcement on, every place the allowlist is checked refuses an unlisted address: sign-in, the console guard, binds, and the per-row operator check from HYG-008.
2. **Emergency command.** `pnpm vendor:allow-address --cidr <ip/cidr> --label "<label>"`, run on the server terminal only, like `vendor:bootstrap` (DEC-036).
   - Its password prompt is hidden.
   - It adds an address and writes a vendor-log row.
   - It works when every platform owner is locked out. It never runs from the web.
3. **Passkeys (optional):**
   - **Validated 2026-11-05:**
     - The passkey plugin is **not** inside the installed `better-auth` package. `node_modules/better-auth/dist/plugins` lists no passkey.
     - It is the separate package `@better-auth/passkey` (npm, latest 1.7.17; documentation https://better-auth.com/docs/plugins/passkey; built on SimpleWebAuthn).
     - The project pins `better-auth` 1.7.15. Adding the plugin needs:
       - the `@better-auth/passkey` version matching the installed `better-auth` (check its peer dependency);
       - a dependency decision, because AGENTS and native-first say "no new dependency without reason". Here the reason is DEC-042 (3).
     - **Still to check:** server and client setup, the schema it adds (a migration), the `rpID` per surface (the vendor host), and the interaction with the two-factor plugin and the vendor surface (`basePath`, `__Host-vendor` cookies).
   - The vendor surface offers "Tambah passkey" in Keamanan, with a recommendation text.
   - Sign-in with a passkey counts as the second factor for the session (`second_factor_at`), if and only if the library verifies user presence and verification for it. Validate this; otherwise a passkey sign-in still asks for TOTP.
   - TOTP stays mandatory as enrolled: a passkey is an addition, never a replacement, unless a later decision changes that.
   - The clinic app is unchanged.
