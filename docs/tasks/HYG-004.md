# HYG-004 — Test hook timeout under a busy full suite

Status: PASS (local; CI after push) · Risk: R2 (test configuration only; no product code) · Owner: Paduka Ongki · Executor: pi (cc/claude-opus-5-5) · Review: codex r1, GPT (cx/gpt-6.1-sol, read-only pi) r2 and final

## Why

Investigating the T-026 full-suite failure of 2026-11-04 15:00 (owner instruction "lanjutkan rekomendasi terbaikmu"): three full runs on `1cbdeec`, each started at a one-minute load ≤ 4 with no other suite running. All three passed every test (759), but run 3 exited 1: `tests/vendor/bootstrap.test.ts` failed with "Hook timed out in 10000ms" in its `afterAll`. The full suite raises the host load by itself (to 8.5 in that run).

Every integration file closes its harness in `afterAll` (pools, `DROP DATABASE … WITH (FORCE)`, `DROP ROLE`). 29 such hooks run on vitest's default 10 s hook timeout; `beforeAll` hooks in the slow files already pass 120 s by hand. A hook timeout fails the file while every test in it passed — the same signature as the T-026 15:00 failure (its output was not kept, so that one is inferred, not proven).

Not a `TASKS.md` task: hygiene the owner authorised directly, like HYG-001–003.

## Change

- Add `vitest.config.mts` with `test.hookTimeout: 120_000` (the value the slow `beforeAll` hooks already use) and nothing else. No `testTimeout` change: test bodies keep their explicit or default limits, so a slow test still fails.
- Test discovery must not change: the list of test files (`vitest list --filesOnly`) is identical before and after (46 files).
- No per-file edits; per-file `beforeAll(…, 120_000)` stay as they are.
