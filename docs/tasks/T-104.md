## What is built (migration `0121_subledgers`; DEC-115)
- **Readers** (owner, finance, auditor; the actor lock first): `subledger_rollforward(from, to, branch)` returns every ledger's opening,
  terms, closing, per-branch and per-dimension splits, the check level and its comparator, the VAT state (PKP, cutover, per-period D-A
  recording), the staff names of commission recipients and receivable aging. `subledger_export(kind, from, to, branch, staff)` (owner,
  finance; audited `export / subledger`) writes a ledger's movements or a transaction set (payments, invoice lines, commissions per recipient
  with totals, stock movements) — ids, document numbers, branch codes and amounts only; no journal kind (A-14).
- **Movements** (`subledger_movements`, not granted): one row per fact, ledger and term, dated by the fact's own local business date, from
  the immutable facts of plan r5 §2.2; simulated money excluded. Patient balance and receivables gross; the two net-of-VAT liabilities
  (paid-not-delivered, package liability) are their money movements minus the VAT movements of their own VAT objects (the same dated facts,
  seam events and residues as the VAT ledger) — exact by construction, no mutable session field read (r2). Each row carries `incomplete`
  (a pre-cutover movement of an object with a residue).
- **D-A1**: `vat_input_credits`, `vat_payments` (append-only; correction = negative row with a 10–500 character reason; the running total of a
  tax period never below 0 under a tenant lock) written by `vat_input_credit_record` / `vat_payment_record` — finance only, PKP at the end of
  the period from the tax-profile history (`ERR_NOT_AVAILABLE: not_pkp`), idempotent, audited (`vat_input_credited`, `vat_paid`), no event.
- **D-B2**: the patient-balance ledger attributes each debit (use, cash refund) to the credits it consumes in `seq` order (FIFO; overlap of
  cumulative intervals), on the credit's branch at the debit's time. Σ origins = the stored balance per patient.
- **D-C1**: `vat_cutovers` (one row per tenant existing at 0121; a later tenant has none: its history is all recorded), `vat_cutover_openings`
  (per canonical VAT object: position at cutover − dated known movements, computed once by `vat_cutover_open`). A report ending before the
  cutover claims no VAT closing; a straddling one says its opening is incomplete; the residue is the term "Selisih sebelum cutover".
- **C-7 seams** (`vat_events`, signed change of the object's VAT position): S1 `package_execution_finish` (+ session VAT first due at
  delivery — only for a package whose invoice was not PKP at issue), S1b / S5b (a PKP-at-issue package's recognised VAT moved to the delivered
  session: package −d / session +d, net zero), S2 `receivable_convert` (+ VAT recognised at conversion), S3 `interrupted_to_balance` (− reversal), S4 `package_close_do`
  (− difference-line reversal; − package reversal over the value after its own sync), S5 `package_sync_vat` branch B (− (pool − open)),
  S6 `deposit_apply_do` (deposit − V, line + v). Each re-created with added INSERTs only (`tests/db/subledgers-drift.test.ts`: the new body
  minus the added lines equals the old body line for line).
- **Page** `/keuangan/kewajiban` (UX-22 ▸ Kewajiban): K5 prepaid liabilities first, receivables with aging, commission, VAT (cutover labels,
  "PPN masukan / Setoran PPN belum dicatat" per PKP month, finance forms), cash/bank and clearings, Ekspor (owner, finance); the auditor reads.

## Check levels (plan r5 §2.5, complete in r2)
- Stored historical stock: patient balance per account (`balance_after` of the last entry vs the ledger per account), booking DP per deposit.
- Object level: receivables per object (history vs ledger; today's stored columns); every package, open and closed, against an independent
  reconstruction from the stored package state (paid − moved, its stored VAT position, redeemed sessions, live difference lines; run when the
  report ends today; packages with a residue skipped); commission per recipient (entitlements + adjustments − paid lines) and each paid batch
  line's carry-forward identity and carry-in = the previous carry-out.
- Identity + cross-ledger: receipts (Σ allocations ≤ each payment; the cash/clearing receipts = the real payments), inter-branch nets to 0.
- The page's badge reports the mismatch count; an incomplete ledger shows "Riwayat belum lengkap" and no numeric opening/closing. A
  comparator that did not run (branch view, a report ending before today) shows "Belum dicocokkan"; skipped residue packages show
  "Sebagian dicocokkan" — never "Cocok" (r3).
- Commission carry-in is checked against the writer's own rule (`commission_carry_in`): the latest earlier batch line whatever its state,
  0 when that remainder had become a staff receivable by this batch's submission (r3).

## Known limits (stated, not hidden)
- A-12: VAT on a single treatment / product delivered before payment is recognised at payment or conversion (no delivery writer does it) —
  HYG-023 candidate (`HYG-A12-PROPOSAL.md`), after T-104.
- Pre-cutover VAT changes that no dated fact explains (conversion, an interruption that cannot be reconstructed, package close) sit in the
  object's cutover residue; a ledger that includes them claims no closing until every residue row of the view is inside the period, by
  each row's own local date (its object's branch time zone; r3) (Panel 2 R1). A provable interruption (the line's only one before the
  cutover, no DP applied before it) is reconstructed by the writer's formula from the pre-cutover facts only; a later fact never changes it.
- Writer finding (reported, not changed): `interrupted_to_balance` on a partly paid taxable addition reverses VAT in proportion to the line
  total, leaving part of the recognised VAT on money that moved to balance (e.g. 16,500 of 33,000); the ledgers show the facts as they are.
- Branch views: commission paid and the D-A facts carry no branch and appear tenant-wide only.
