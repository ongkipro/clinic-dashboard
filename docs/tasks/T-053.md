## Design (proposed)

**Signing** (migration 0071):
- `examinations.state` gains `signed`; columns `signed_at`, `signed_by`, `signed_as` (acting role, PR-3), `content_hash` (sha256 hex of the canonical record content at signing). CHECK: signed ⇔ the three set.
- `record_sign(p_exam, p_code_ok boolean?)` — see open point 1 for the second factor. Author only, draft only, open visit not required (a doctor may sign after close? — open point 4). Sets visits.doctor → done. Event `ExaminationSigned` (ids). Audit `record_signed` with acting role from the session (PR-3 is then automatic: `audit_append` records `app_acting_role()`; `signed_as` stores it on the row).
- The T-052 guard already freezes a non-draft examination and its parts; it is extended so `draft → signed` is the only state change, done only by `record_sign` (the guard checks the signed columns are set together).

**Versions and corrections** (CLIN-023, PR-13):
- `record_versions`: (tenant, branch, examination, version n ≥ 1, content jsonb — the canonical SOAP/template/vitals/ICD/marks/verifications snapshot, content_hash, kind `original` | `correction`, reason, created_by, created_as, created_at, approval_id null). Version 1 is written at signing (the snapshot of the signed content). Never updated or deleted.
- `record_correct(p_exam, p_delta jsonb, p_reason)`: author only; the delta names only the changed fields (allowlist: subjective, objective, assessment, plan_note, template values, vitals, icd10_codes — marks and verifications not correctable here, open point 3); refuses an empty or no-op delta (net delta only, CLIN-023).
  - Within 48 h of `signed_at` (wall clock; exact boundary tested at 47:59 and 48:01): writes version n+1 at once (`kind correction`, `delta` = only changed keys, `content` = full new snapshot), audited `record_corrected`, event `RecordCorrected` (ids).
  - After 48 h: writes a pending correction row and `approval_request('record_late_correction', 'record_correction', id, reason, branch)` (new approval type: requester doctor; approvers records_officer, facility_head; owner_self false). The version is created only when the approval is decided approved (trigger on approvals like `catalog_review_sync`); rejected/cancelled keep it as a rejected request. The prior version always stays readable (PR-13 scenario).
- The examination row itself never changes after signing; "current content" = the latest version's content. Readers show the current version and list earlier versions (CLIN-014 timepoints: a new examination at a later visit is a new record, not a version — tested).

**Patient copy** (PR-49):
- `record_copy_request(p_patient, p_reason)`: FO, records officer (and facility head?) — open point 5; logs `record_copy_requests` (patient, requested_by/as, at, scope = signed records of the merge cluster, count) and returns the canonical content of the signed records (latest versions) for rendering.
- PDF: generated in TS without a new dependency — a minimal hand-written PDF 1.4 writer (text only, Helvetica, A4, one record per page section) in `src/modules/clinical/records/pdf.ts`, ≤ 150 lines, test parses the output for `%PDF-`, the patient name and each record's date. Audit `record_copy_produced` (content-free). Delivery to the patient (WhatsApp / print) is outside this task.

**Retention** (05:218, PRIV-3):
- No delete path exists (guards). Add `retention_until(p_patient)` = last visit + 25 years (reader for the future disposal job), and the guard refuses deletion of signed records and versions always (disposal is a later, authorized process). Test: no role, including the database owner through the app path, deletes a signed record or a version.

**RLS:** `record_versions`, `record_corrections`, `record_copy_requests` — clinical class; readers `exam_readable` (doctor, FH, RO) for versions/corrections; copy requests readable by RO, FH, FO (their own branch) — content-free rows (no record content stored in the request).

**Module** `src/modules/clinical/records/records.ts` (sign, correct, versions, copy request + PDF); `tests/clinical/records.test.ts`. Scope expansions: `tests/rls/rls.test.ts` (allow-list), `tests/rls/authority-clock.test.ts` (writers), `tests/db/*-drift.test.ts` if an existing function is re-created (the T-052 guard), `tests/isolation/cases/*` only if a route exists (none in this task — the readers are module functions; isolation via the module's cross-tenant test).

## Open points (for plan review)

1. **Second factor at signing** ("PIN/OTP", 19:87): verify a TOTP code in the server action via Better Auth `verifyTOTP` before calling `record_sign`, and pass nothing to SQL (the database cannot verify TOTP). Recommend: the module takes a `verified: true` assertion only from a server-side step-up helper; the SQL writer requires the session's second factor to be enrolled (doctor is a TOTP role already, PR-3). A UI task wires the prompt.
2. **48 h clock start:** from `signed_at` (the record's signing), not from the visit or the draft's creation. The PR-13 scenario says "input 50 hours ago" — recommend `signed_at` since only signed records need correction; drafts are edited freely.
3. **Correctable parts:** SOAP, template values, vitals, ICD-10 in the delta; marks and intake verifications fixed at signing (a mark correction = a new examination timepoint or a later task). Confirm.
4. **Signing after the visit closes:** allow (a doctor may sign shortly after the FO closes the visit) — the examination stays a draft until signed; recommend allowed, author only.
5. **Who requests a patient copy:** FO (scenario), records officer, facility head; doctor? Recommend FO, RO, FH.
6. **"Tanda Tangani" UI** in `/pemeriksaan/[visitId]` is outside the Allowed Paths: either a declared scope expansion here (small: one form + step-up prompt) or left disabled until the next clinical UI task. Recommend a scope expansion, since UX-8 names it as the primary action and T-052 shows it disabled with the reason "T-053".
7. **Content hash canonicalisation:** `jsonb` text of the canonical snapshot (keys sorted by jsonb) hashed with `sha256(convert_to(..., 'UTF8'))` in SQL; the PDF is not hashed.
