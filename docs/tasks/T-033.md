## Design (revised after the plan review e84e09b0 and owner decision DEC-046)

- **Tables (tenant-shared, RLS, scope_map):**
  - `catalog_items` (id, tenant_id, kind service/product/package/material, code unique per tenant, created_at/by). Never deleted.
  - `catalog_versions` (id, tenant_id, item_id, version 1..n per item; state; commercial fields: name, tax_category (BILL-6: exempt_medical, taxable_service, taxable_goods, non_object) + tax_basis, normal_price integer rupiah ≥ 0, control_count, control_validity_days, booking_dp_enabled + booking_dp_amount, min_dp_pct, installments_allowed, validity_days, material_formula jsonb, commission_scope (subset of the BILL-15 contributions guiding_bc, closing_bc, new_patient, performer); clinical fields: indications, contraindications, consent_template, delegation (text; T-034 adds structured staff eligibility); created_by/as, approval_id, decided_at, referenced_at). DATA-62 columns stay with T-034, branch prices with T-035.
- **States and transitions (only these; a trigger refuses the rest):**
  - insert as `active` (no clinical change) or `pending_review` (with its approval);
  - `active` → `superseded` (only when another version of the item becomes active);
  - `pending_review` → `active` (approved) | `rejected` | `cancelled` (the requester withdraws through `approval_cancel`).
  - At most one `active` and one `pending_review` per item (partial unique indexes). A new item whose first version carries clinical fields has no active version until approved: listed as "Menunggu review klinis", not sellable. Retiring an item is deferred (not in PR-41's scenario; T-034's Master Layanan or a later task).
- **Content immutable from insert (CLIN-011):** every content column is fixed when the row is written; only state, decided_at and (set once) referenced_at change. `catalog_version_reference(version)` sets referenced_at once (for later sale/booking writers). No delete, no truncate.
- **Publishing (`catalog_publish(item or null + kind/code for a new item, fields jsonb, reason)`, SECURITY DEFINER, `tenant_actor_lock`, then the item row `FOR UPDATE`):**
  - Owner, Admin Pusat, Manager publish (07 row, IAM-11); facility head, pharmacist and every other role are refused.
  - **DEC-046 (3):** refused while the item has a version in `pending_review` (named; withdraw or wait for the decision).
  - Clinical change = any of the four clinical fields differs from the active version after normalization (trimmed; empty = null), including clearing one; a new item with any clinical field set is a clinical change.
  - No clinical change → `active` at once, the previous one `superseded`. Clinical change → `pending_review` plus an approval of the new type `catalog_clinical_review` (requester owner/admin_pusat/manager; approver facility_head, owner), tenant-wide (branch null). The previous version stays active (PR-41).
- **Approval integration (every path):**
  - A sync trigger on `approvals` (as `setting_draft_sync`): when a `catalog_clinical_review` approval leaves `pending`, its version becomes active (superseding the previous) / rejected / cancelled in the same transaction, audited, `CatalogVersionPublished` event (ids only). So `approval_decide`, `approval_cancel` and Persetujuan need no catalog-specific path.
  - **DEC-046 (1):** any active facility head of the tenant decides it (tenant-wide); the owner only while no facility head other than the requester could; requester ≠ approver (engine). The existing D2 helpers become "tenant clinical approval" helpers covering both `setting_change_fh` tenant drafts and `catalog_clinical_review`: the `approvals_read` policy, `approval_decide`'s owner-fallback check, `approval_fh_available`, `approval_owner_decides_fh` are re-created with that one change (drift test).
  - Inbox: `APPROVAL_TYPES` gains the type; the owner filter covers it (scope expansion: `src/modules/approvals/inbox.ts`, `tests/approvals/inbox.test.ts`).
- **Readers (DEC-046 (2)):** `catalog_versions` rows (all columns) readable by owner, admin_pusat, manager, facility_head, doctor, nurse, therapist, pharmacist; pending/rejected/cancelled only by owner, admin_pusat, manager, facility_head (and the requester). Every other member reads the commercial projection of active versions through `catalog_commercial()` (definer, no clinical column). `catalog_items` readable by every member.
- **UI (UX-25, `src/app/(app)/katalog/`):** list (active name, kind, price, "Menunggu review klinis" badge), detail (active version; clinical section only for the clinical-content roles; version history; the pending change with Tarik Ajuan for its requester), form "Simpan" / "Minta Review" for publishers. The facility head reviews in Persetujuan (link from the pending change). Roles without publish rights read only.
