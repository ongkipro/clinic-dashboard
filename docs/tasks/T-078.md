### 4.3 Refund flow
- **Room** (shared ceiling, `0091:712`): `kasir_line_paid(line) − moved_to_balance − Σ amount of the line's refunds in requested|approved`. `amount > room` → `ERR_VERSION_CONFLICT: refund_above_paid` (UX-14 blocked "refund above paid amount"). Simulated money never counts (BILL-29; `kasir_line_paid` already excludes it).
- Refused: invoice not `issued`; a package line (`ERR_VERSION_CONFLICT: package_line` — "Batalkan Paket" is the path); a line with an unpaid remainder (`line_total − cancelled − receivable − paid > 0` → `line_unpaid`, §7 point 5); a line with `receivable_amount > 0` (`line_on_receivable`).
- **Delivered** (decided once, stored): product line — a `handed` dispensing for the line (counter) or for the visit with `stock_items.catalog_item_id = line.item_id`; service/addition line — a finished, counted execution on the visit for that service (`package_plan_service` / `plan_item_id`). Otherwise undelivered.
- **Balance (default, PR-21, B-11):** in one transaction: lock line; `moved_to_balance += amount`; VAT reversed `v_vat = vat_recognised × amount ÷ line_total`, capped at `vat_recognised − vat_reversed` (the `interrupted_to_balance` formula, `0091:1801`); `balance_post(…, 'from_refund', amount, {source_kind:'refund', source_id}, key 'refund:<id>')` → BalanceMoved; refund `paid`; event `RefundPaid{refund_id, destination:'balance'}` (notification only, `11:120`); `kasir_visit_payment`; audit `money_correction` `refund_to_balance`. No approval; no cash leaves the drawer.
- **Cash (exception, B-04, BILL-12, SET-11):** request → refund `requested`, room reserved, `approval_request('refund_exception','refund', id, reason, branch, amount)`. Approval decided in Persetujuan (`approval_decide`, requester ≠ approver, `ERR_APPROVER_IS_REQUESTER`):
  - approved → `refund_exception_sync`: refund `approved`, event `RefundApproved{refund_id, approval_id}`;
  - rejected/cancelled → refund `failed` (`failure_code` `rejected`/`cancelled`), room freed; the UI offers "Refund ke Saldo".
  - `refund_pay`: in one transaction, `balance_post('from_refund', +amount)` (BalanceMoved) then `balance_post('cash_refund', −amount)` (no event from balance_post), line `moved_to_balance` and VAT as above, refund `paid` with method, event `RefundPaid{refund_id, destination:'cash', method}` (owns Dr balance / Cr tender, `11:120`). This is exactly S9-J1 + S9b-J3 and S15-J1 + S15b-J3.
- **Clinic-caused DP refund:** stays in T-077 (`deposit_refund_clinic`, no B-04 approval, BILL-13). Not duplicated.
- **Stock (scenario 15 J2, ProductReturned COGS only):** when `returned_quantity` is given on a delivered product line (unopened and usable, staff-confirmed): ≤ handed − already returned; back to the dispensed batch and depot (`dispensing_lines`) by `stock_move_depot(…, 'patient_return', +q, NULL, 'refund', refund_id, …)`; valued by `stock_movements_value` (`0080:146`) at the last moving average; event `ProductReturned{refund_id, dispensing_id}`. An opened/unusable item is not returned to stock. Scenario 9's material return and waste use the T-062 material paths (`material_return_decide`, `material_waste`), not T-078.
- **Consultation re-charge (BILL-21/B-02):** T-079 (depends on T-078). T-078 creates no re-charge line.
