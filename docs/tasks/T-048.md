## Design

**Migration `0064_queue.sql`:**
- `queue_tickets` (branch-scoped, DATA-52): `id`, `tenant_id`, `branch_id`, `queue_date` (branch-local date), `seq` (1..), `prefix` (from SET-40 `prefiks_loket` at issue), `visit_id` (unique; every ticket belongs to one visit), `state` (`waiting`, `called`, `skipped`, `done`), `called_at`, `called_by`, `room_id` (nullable: the room it was called to), `created_at`. Unique `(tenant_id, branch_id, queue_date, seq)`; composite FKs; checks. Number shown = `prefix || '-' || lpad(seq, 3, '0')` ("A-012").
- Issuing: `queue_issue(p_visit)` (internal): the next `seq` for the branch's day under an advisory lock per `(tenant, branch, date)`; called by both writers below. Every visit (walk-in or booked) gets a number at check-in, so the queue covers the whole day (open point 1).
- `visit_walk_in(p_patient)` (definer; `visit_actor`; branch = the actor's active branch, refused when none; patient of the tenant; one open visit): inserts a `walk_in` visit and its ticket; event `VisitCheckedIn` (ids only). Returns `{visit_id, number}`.
- `visit_check_in` (T-047) is re-created to issue a ticket too (drift test `0063 → 0064`, exact patch).
- `queue_call(p_ticket, p_room)`, `queue_skip(p_ticket)` (definer; FO/cashier, manager, owner, admin pusat; ticket's branch scope): waiting|skipped → called (with room), waiting → skipped; a called ticket can be called again (re-call). "Pindah" (move to another room) = call with another room. Done is set when the visit closes (re-created `visit_close` sets `done`).
- `queue_board(p_branch)` (definer; staff readers as the board): today's tickets with the patient name for staff.
- **TV pairing** (NAV-8): `queue_displays` (branch-scoped): `id`, `tenant_id`, `branch_id`, `label`, `token_hash` (sha256, unique), `created_by`, `created_at`, `revoked_at`. `queue_display_pair(p_branch, p_label)` (manager, owner, admin pusat; returns the one-time token, only its hash stored), `queue_display_revoke(p_display)`. `queue_display_feed(p_token_hash)` (definer, outside any tenant context, like `staff_invite_lookup`): returns for the display's branch only `{orientation, voice, current: [{number, room}], next: [number]}` — numbers and room names, never a patient name, MRN or id; a revoked or unknown token returns null.
- RLS: both tables readable by the board roles of the branch; `clinic_app` SELECT only (tickets) and none on `token_hash` (column grant); `support_object_kinds` (`queue_tickets` personal: linked to a visit; `queue_displays` config); operator policies; scope map.

**Module `src/modules/visits/queue/queue.ts`:** `walkIn`, `callTicket`, `skipTicket`, `queueBoard`, `pairDisplay`, `revokeDisplay`, `displayFeed` (idempotent writers through `runCommand`, go-live gate).

## Plan review r1 (Argon `7e69fb75`: REVISE; the five open points accepted) and the revised design

- **P1-1 token never in the database or the idempotency record:** the token is generated in Node (`randomBytes(32)` base64url), only `sha256` hex goes to `queue_display_pair(p_branch, p_label, p_token_hash) RETURNS uuid`; the idempotent command returns only the display id, and the token is attached outside it on the first answer (a replay does not show it again; the manager pairs again).
- **P1-2 settings outside a tenant context:** `queue_display_feed` resolves SET-40 against the display's own tenant and branch (branch version, then tenant, then default) and serves only a `live` or `suspended` tenant; a test changes SET-40 and reads the feed outside any context.
- **P1-3 active branch:** the queue writers and the board act on the actor's **active** branch; for Level 3 roles (manager, FO) a target branch other than the active one is not found; Owner and Admin Pusat on "Semua Cabang" name the branch (`p_branch`), refused when none. So every action records the branch it acted on (scenario PR-84).
- **P1-4 contract and guards:** both tables get `UNIQUE (tenant_id, id)`, composite restrict FKs (visit, room, staff), state and stamp checks (called ⇔ called_at, called_by, room; waiting ⇒ never called), `UNIQUE (tenant_id, visit_id)`; `queue_displays.revoked_by` with `revoked_at ⇔ revoked_by`; column grants on `queue_displays` for `clinic_app` **and** `clinic_operator` without `token_hash`; always-enabled guards (no delete, identity fixed, nothing after done / revoked; truncate refused); `queue_call` needs an active room of the branch and refuses a done ticket; every writer audits (ids and codes only).
- **P2-1 search for all four board roles:** the walk-in search on Antrean uses its own definer `queue_patient_search(p_query)` (the four board roles; name, MRN or phone; at most 20 rows; the minimal projection: id, MRN, name, birth year, masked phone; query never logged) instead of `patient_matches` (FO/CS only).
- **P2-2 nav:** `antrean` for `O AP M FO`; the quick action `pasien-datang` points to `/antrean?aksi=datang`. `queue_board` returns tickets, the branch's active rooms and its displays (no token hash).
- **P2-3 scope expansions** (ledger, before building): `src/app/layar-antrean/**` (no-referrer, noindex), `src/lib/hosts.ts` (`layar-antrean` reserved), `src/components/shell/nav.ts`, `tests/rls/rls.test.ts`, `tests/rls/authority-clock.test.ts`, `tests/isolation/cases/antrean.cases.ts`, `tests/context/stale-context.test.ts`, `tests/platform/hosts.test.ts` if its reserved list is asserted. The `0063 → 0064` drift check lives in `tests/visits/queue.test.ts`.
- **P3-1** the shown number pads to at least three digits without truncating (`lpad(seq, greatest(3, length(seq)))`).
