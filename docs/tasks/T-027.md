## Design

### Data (migration 0051, the only migration of this wave)
- `onboarding_checklist_items` (platform table, TEN-16, `scope_map` platform): `tenant_id`, `branch_id` (null = tenant level), `item` (catalogue key), `status` (`open` | `done` | `not_applicable`), `note` (blocker or reason, ≤ 500), `owner_staff` (vendor staff, nullable), `updated_by`, `updated_at`. Unique `(tenant_id, branch_id, item)` nulls not distinct. Never deleted (guard trigger); no table privilege for any application role.
- Catalogue (PR-59): tenant level `entity_tax` (entity and tax status), `catalog`, `staff_credentials`, `money_settings`, `payment_port`, `waba`, `satusehat`; branch level `branch_setup`. The three integrations "when used" may be `not_applicable` with a reason; every other item needs `done`.
- Seeding: on provisioning → onboarding (AFTER INSERT trigger on `tenant_lifecycle_events`, beside the T-024 grant trigger), every tenant item and one `branch_setup` per existing branch; a branch inserted while the tenant is onboarding gets its item (AFTER INSERT trigger on `branches`).

### Go-live gate
- In `tenant_lifecycle_transition` (latest body 0038), staff branch, `onboarding → live` only: refuse with `ERR_FORBIDDEN: go_live_blocked:<kind>:<key>` naming the first blocker in a fixed order: `checklist:<item>[@<branch code>]` (open item), `vendor:<reason>` (`vendor_go_live_blockers()`, includes `vendor_staff_maker_checker` = fewer than two vendor staff), `clinical:<obligation>` (an obligation of gate `clinical_go_live` whose tenant evidence is not open). Reactivation (suspended → live, request path) is not gated.
- Go-live date: `tenant_go_live_at(tenant)` = time of the first `onboarding → live` lifecycle event (exists today; no new column). PR-61 billing reads it later; no invoice is created here.
- `vendor_console_tenant_advance` (latest body 0049) maps the new refusal to reason `go_live_blocked` and returns the blocker string (`blocker`), so the console names it. Re-created from its 0049 body with one asserted edit; drift test pins the diff.

### Console (HYG-008b rule: authority re-check before every exit after the guard)
- `vendor_console_checklist(token, ip, tenant)`: reader (all vendor roles): items with status, owner, note, branch code; current blockers (the same function the gate uses), go-live date.
- `vendor_console_checklist_set(token, ip, tenant, branch, item, status, note, owner)`: onboarding or platform_owner, tenant in onboarding; `not_applicable` only for the three integration items and needs a note; logged (`vendor_log`, action `checklist_set`).
- UI `src/app/vendor/onboarding/**` (UX-41): list of onboarding tenants → per-tenant checklist (tenant items, then each branch), owner, status, blocker; "Tandai Siap Live" (platform owner) enabled only when no blocker, otherwise disabled with the named blocker; states loading, empty, error, success, blocked; 390/820/1180/1440.
