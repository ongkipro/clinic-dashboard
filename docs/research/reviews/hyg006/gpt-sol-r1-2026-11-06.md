## Review

- **Finding — MEDIUM (P1): The slash heuristic can hide real database DDL and report comments as DDL.**  
  **Location:** `tests/rls/harness-lock.test.ts:104–116`.

  The previous character is insufficient to distinguish a regex literal from division. Two valid JavaScript examples demonstrate both errors by tracing the supplied scanner:

  ```ts
  if (ok) /"/.test("https://x"); await q(`CREATE DATABASE x`);
  ```

  After `)`, the regex is not recognized. Its `"` opens a false string, the opening quote before `https` closes it, and `//` then hides the rest of the line—including the actual CREATE. The scanner returns no offender.

  ```ts
  let x = 1; const n = x++ / 2; // CREATE DATABASE example
  ```

  After `++`, division is incorrectly recognized as a regex. It consumes the first slash of the comment as its closing delimiter, leaving the comment text visible and producing a false offender.

  **Concrete fix:** Use parser-derived regex-literal ranges for TS/JS files rather than this preceding-character heuristic; the existing loop can copy those ranges without interpreting their quotes. Add both examples as structural-test fixtures. The existing `regex-blind-scan` mutation proves the supplied fixture needs regex awareness, not that this heuristic correctly supplies it.

- **Finding — MEDIUM (P1): Attaching the unlock error can replace the original operation error.**  
  **Location:** `tests/rls/harness.ts:145–152`, particularly line **150**.

  The contract requires the operation error to retain precedence, but assigning `error.cause` can itself throw. For example, a callback throwing `Object.freeze(new Error("operation failed"))`, followed by the injected unlock failure already supported by these tests, reaches the assignment and throws a `TypeError` instead of the original error. The connection has been ended, but error identity is lost.

  **Concrete fix:** Make reading/attaching `cause` best effort inside its own guarded block, then unconditionally rethrow the original error. Add a frozen-error case and verify an existing cause remains unchanged. Document that attaching a cause is conditional on the error permitting it.

- **Finding — LOW (P2): Test 11 still has an unbounded report barrier until the overall test timeout.**  
  **Location:** `tests/rls/harness-lock.test.ts:391–397`.

  Resolving on any report line improves the observer-failure case, but `await reported` has no failure bound or acquisition-rejection handling. The supplied `no-holder-report` mutation demonstrates the remaining path: no line resolves the barrier, while the acquisition cannot complete because the test releases its holder only after that barrier. Failure therefore occurs at the 60-second test timeout. If acquisition rejects before reporting, `p` also has no rejection handler while the test waits.

  **Concrete fix:** Bound the report barrier using a failure-only deadline and race it against unexpected acquisition settlement. In `finally`, release/end the holder and settle the operation promise before restoring the console spy. This preserves report-driven success without leaving failure cleanup to the test timeout.
