## Open points (for the reviewer)

1. **Holdings under the T-060 invariant.** Proposal: `stock_movements` gains `depot_id` (NOT NULL after backfill) and `depot_balance_after`; `batch_holdings` (tenant, branch, depot, batch, item, quantity ≥ 0, unique (depot, batch)). The movement insert trigger sets both the batch quantity and the holding (inserting a zero holding first when missing); a holding guard accepts a quantity change only as the newest movement of that (batch, depot) continuing it. Then Σ holdings of a batch = batch quantity by construction (both start at 0, every movement moves both by the same amount). Backfill in 0078: one `gudang` depot per existing branch, holdings = current batch quantity, existing movements and vials get the gudang (guards disabled only inside the migration, re-enabled ALWAYS).
2. **Default depot.** Proposal: every branch has exactly one active `gudang` marked default (partial unique). New branches: an AFTER INSERT trigger on `branches` creates it (so `branch_create` and tenant provisioning need no change). `stock_receive_into` puts stock into a named depot of the branch or the default gudang.
3. **Intra-branch transfer (PR-89).** One command `depot_transfer(p jsonb)`: from depot, to depot (same branch, different), lines (batch, quantity); state `posted` at once; per line two movements `transfer_out` (−q, source depot) and `transfer_in` (+q, destination depot) on the same batch, linked by the transfer id (`source_kind 'depot_transfer'`, `source_id` = transfer id) and a `leg` column (`out`/`in`). The batch quantity is unchanged after both legs. Availability: the source holding locked `FOR UPDATE` (holdings in id order); a line beyond the holding's free quantity (quantity − open vial remaining in that depot) refuses the whole transfer with `ERR_STOCK_INSUFFICIENT`.
4. **Inter-branch transfer (PR-17).** Two steps: `branch_transfer_send(p)` (state `sent`: the `transfer_out` legs on the source batches leave the source depot and branch; the stock is in transit, held nowhere) and `branch_transfer_receive(transfer, to depot?)` (state `received`: the `transfer_in` legs on the destination branch's batch of the same item, batch number and expiry — created at quantity 0 when missing — into the named depot or the default gudang). Also `branch_transfer_cancel` while `sent` (returns the stock to the source depot with `transfer_in` legs on the source batches, state `cancelled`). Conservation: Σ out = Σ in per transfer once received or cancelled; a reader shows in-transit totals.
5. **What may be transferred.** Proposal: only fit stock (CLIN-019: not expired, quarantined or recalled; `stock_unfit_reason` null) and never an open vial's remainder (it stays in its depot). Moving held stock (e.g. to a quarantine shelf) is not in PR-89; recalled returns to supplier are T-066.
6. **Idempotency (DATA-63 "a replayed transfer key returns the original result").** Proposal: each command runs through `runCommand` (key in `idempotency_records`); the transfer row also stores the command key (unique per tenant), so a replay through `runCommand` returns the stored result and a second write with the same key cannot exist. Concurrency: two transfers on the same source holding serialize on its row lock; the second sees the reduced quantity and refuses.
7. **Counts and vials per depot.** Proposal: `opened_vials.depot_id` (a vial is open in one depot; one open vial per (batch, depot)); `stock_vial_open(batch, depot?)`. `stock_count_lines` gain `depot_id` (a line per holding; unique (count, batch, depot)); `stock_count_start(blind, items, depot?)` counts the holdings of one depot or all; apply writes the adjust movement on that depot. T-060's tests stay green (one gudang per branch). `stock_fefo` and `stock_assert_fit` gain an optional `p_depot` (null = whole branch, as T-060).
8. **Who.** Depots: create, rename, deactivate (never delete; a depot with stock cannot be deactivated) by pharmacist at its branch, purchasing naming a branch, admin pusat. Transfers: intra-branch and send by pharmacist at the source branch or purchasing; receive by pharmacist at the destination branch or purchasing; cancel by the sender or purchasing. A `ruang` depot may name a `rooms` row of kind treatment at the same branch (T-064 issues into it). Readers as T-060 (owner, admin pusat, finance, purchasing, auditor tenant-wide; manager, pharmacist their branches); in-transit rows visible to both branches' readers.
