## Design

**Search (`patient_search(p_query text, p_filters jsonb, p_limit int, p_after text)`, definer, `approval_actor`, the 13 identity readers):**
- Matches name (contains, escaped), MRN (exact), phone (digits, suffix; local `0` → `62`). Invoice numbers: no invoice table exists before T-071; the invoice branch of PR-76 is deferred to T-071 (open point 1).
- Projection: id, MRN, name, birth year, masked phone, registered branch name, **visit status** (open visit today: "Sedang berkunjung" with the branch; else the last visit date from `visits`), never diagnosis or clinical content. Clinical roles additionally get "last visit" only (allergies arrive with T-052); finance-only columns (balance, receivable) arrive with M4 — the page shows the columns the data supports now.
- "Only for allowed branches" (PR-76): patients are tenant-shared (DEC-050: registration branch only); the visit status shows only visits at the caller's allowed branches.
- Filters (the subset backed by data now): registered branch, last visit (within 30 / 90 days / never), "sedang berkunjung". Tag, package, balance, receivable and source filters need tables from later tasks (open point 2).
- Keyset pagination by (full_name, id), page size 50.

**Rate limit and abuse alert (PR-76):**
- `patient_search_log` (tenant-scoped, no query text: tenant, staff, role, branch, at): one row per search; the function refuses more than **30 searches per minute per staff** (`ERR_RATE_LIMITED` → `CommandError("ERR_RATE_LIMITED")`, a new code? — reuse `ERR_INVALID_INPUT: rate_limited` to avoid a new error code; open point 3) and, when a staff member passes **200 searches in an hour**, raises one notification `patient_search_abuse` to the facility head(s) of the staff's branch (type registered with recipient `facility_head`, subject kind `staff`), at most once per staff per hour. The thresholds are constants (no setting exists; adding one needs a decision, AGENTS "Settings are only the PR-38 list") — open point 4.
- The query string is never stored, logged, or put in a URL: the page posts the query (server action), the log row has no text, and `console.error` paths log only error names. A test greps the captured console output for the query.

**Saved segments (`patient_segments`):** tenant, owner staff, name (2–60), filters jsonb (validated keys), created/updated; private to the staff member who saved them (open point 5); writers `segment_save` / `segment_delete` (own only); read through `patient_segments_mine()`. Saving a segment stores filters only, never the search text.

**Page `src/app/(app)/pasien/page.tsx` + `_components/`:** title "Daftar Pasien"; search box (POST) and filter controls; results list (rows link to `/pasien/[id]`); saved segments (apply, save current filters, delete); states (empty, filtered-empty with Hapus Filter, rate-limited error copy). Marketing gets `marketing_contacts` only (consented contacts: name and masked phone) — a separate small list, no search (open point 6).

## Plan review r1 (Argon `961661c0`: REVISE; open points 1, 2, 4, 5 accepted, 6 with safeguards, 3 rejected) and the revised design

- **P1-1 rate limit without rollback:** `patient_search` is VOLATILE and takes `tenant_actor_lock()` (serializes the counter and the alert dedupe). It writes the log row first; a staff member over 200 searches in the last hour gets one `patient_search_abuse` notification per hour (type seeded with recipient `facility_head`, subject `staff`, not raisable by staff; inserted directly at the actor's branch, or tenant-wide on "Semua Cabang"); over 30 in the last minute the function **returns** `{ok:false, code:"ERR_RATE_LIMITED"}` (the existing TD-51 code, open point 3 corrected) so the log row and the alert commit; the module raises `CommandError("ERR_RATE_LIMITED")` after the transaction.
- **P1-2 allowed branches:** one visibility rule for visits — `app_branch_allowed(branch)` and, for Level 3 roles, a live `staff_branches` row — governs the projection (open visit branch, last visit) and the filters (last visit 30 d / 90 d / never; visiting now). Projection: id, MRN, name, birth year, masked phone, registered branch, open-visit branch, last visit; never clinical content.
- **P1-3 contract:** both tables with `UNIQUE (tenant_id, id)`, composite restrict FKs, RLS (`patient_segments` readable by its owner only; `patient_search_log` by no app role), scope map, vendor classes (log personal, segments config), operator policies; the log is append-only (guard), truncate refused on both. `segment_save` / `segment_delete`: `tenant_actor_lock`, the 13 identity roles, own segments only, name 2–60, filters validated (keys `branch_id`, `last_visit`, `visiting_now` only; never a query), audited; idempotent through `runCommand` with the go-live gate.
- **P2-1 placement and scope:** the actions live in `src/app/(app)/pasien/_components/actions.ts`; the search is a POST (never `ListPage`'s GET search). Scope expansions: `tests/rls/rls.test.ts`, `tests/rls/authority-clock.test.ts`, `tests/context/stale-context.test.ts`, `tests/isolation/cases/pasien-daftar.cases.ts`.
- **P2-2 marketing:** consented contacts only, phone masked on the server, plain rows (no profile link), no search, filters or segments; purchasing and auditor get the permission state.
- **P3-1** `patient_matches` and `queue_patient_search` untouched (no drift); phone suffix matching with raw and `0 → 62` digits; keyset pagination by the last patient id (resolved in the tenant, `(full_name, id) >`).
