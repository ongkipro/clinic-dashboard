## Open points (for the reviewer)

1. **Where the cost lives.** Proposal: `stock_costs` (tenant, branch, item; `quantity` numeric = the branch quantity of the item, `value` bigint rupiah = the inventory value, `last_unit_cost` numeric(18,4) = the average when the quantity last was above 0; `uncosted_quantity` numeric) one row per (branch, item), and `stock_movement_values` (movement id unique, tenant, branch, item, `value` bigint signed, `unit_cost` numeric(18,4), `uncosted` boolean) one row per movement. Both written only by a new AFTER INSERT trigger on `stock_movements` (`stock_movements_value`, ENABLE ALWAYS); no column added to `stock_movements` and no 0077/0078/0079 function re-created (no drift). The average is `value / quantity` (a rate, numeric); every posted amount is integer rupiah.
2. **Valuation rule per movement** (lock: the cost row FOR UPDATE after the batch and holding locks the movement guard took; staff_access serializes the tenant anyway):
   - inflow `receive` with a cost: value = round(q × unit cost) (the receipt cost row, point 3); without a cost (T-060 receipts, opening stock): valued at `last_unit_cost`, or 0 and `uncosted` when there is none.
   - outflow (`consume`, `waste`, `dispense`, `supplier_return`, `adjust` < 0, `transfer_out` to another branch): value = −round(value × q / quantity), the whole remaining value when the quantity reaches 0 (no rounding residue left behind).
   - `adjust` > 0 (count surplus): at the average (`last_unit_cost` when the quantity is 0).
   - legs inside one branch (`issue`, `return`, `transfer_out`/`transfer_in` intra): the out leg is valued as an outflow, the in leg takes exactly the out leg's value (matched by source kind, source id, item, batch number and expiry), so the branch value is unchanged after the pair (BILL-35).
   - inter-branch `transfer_in` (receive at B, or cancel back to A): the value of the matching out leg at A (same value, 11:93).
   Invariant (test after every case): per (branch, item) Σ movement values = `stock_costs.value`, Σ movement quantities = `stock_costs.quantity` = Σ batch quantities; value is 0 when quantity is 0.
3. **How a receipt carries its cost.** Proposal: a new writer `stock_receive_costed(p_branch, p jsonb)` (pharmacist, purchasing; same payload as `stock_receive` plus `unit_cost` bigint rupiah ≥ 0) inserts a `stock_receipt_costs` row (source kind, source id, item, unit cost) and calls `stock_receive_into` with that source; the trigger reads the cost by (source kind, source id, item). T-067's goods receipt uses the same pattern. The T-060 `stock_receive` (no cost) stays as it is (its receipts are valued at the average or flagged uncosted).
4. **Backfill (0080).** Existing stock has no cost: one `stock_costs` row per (branch, item) with stock, quantity = Σ batch quantities, value 0, `uncosted_quantity` = quantity; existing movements get no value row (the invariant counts from the backfill row). No movement is written (DATA-58 spirit).
5. **Pricing uncosted stock.** Proposal: `stock_cost_set_uncosted(p_branch, p_item, p_unit_cost)` by finance or owner: values the uncosted quantity once (an `adjust`-free revaluation row in `stock_cost_revaluations`, value = round(uncosted × unit cost), audited) — or defer to the opening-data import task (DATA-58). Recommendation: defer (no M3 scenario needs it); the readers show `uncosted_quantity` so it is visible.
6. **Readers and roles.** `stock_cost_list(branch)` (item name, unit, quantity, value, average, uncosted) and `stock_movement_value_list(item, branch, limit)`: owner, admin pusat, finance, purchasing, auditor (tenant-wide) and manager at their branch; not pharmacist, not room roles (no money needed). RLS on the new tables through a `stock_cost_readable(tenant, branch)`. Money rows carry no patient: support class `money_total` for `stock_costs` and `stock_movement_values`, `personal` for `stock_receipt_costs` (staff attribution).
7. **Estimated consumption.** Bulk consumption writes no movement (T-062), so it has no value here; room counts post the adjust at the average. The margin report (K7, later) labels "estimasi" from `material_consumption_lines.estimated`; nothing more in this task.

## Plan review round 1 (Argon `3e47be5f`): APPROVE PLAN — notes adopted

Checked against the code: the holding and batch guards (0077:534, 0078:428) accept a change only as the newest movement continuing a stored balance; `'NaN'::numeric(18,4) >= 0` is true in PostgreSQL 16 (only `between` rejects it); `tests/db/contract.ts` requires `id`, `tenant_id` and `UNIQUE (tenant_id, id)` on every tenant table.

- **P2-1 (guards):** `stock_movement_values` stores per movement the signed `value`, the signed uncosted units `uncosted_qty`, and the afters `quantity_after`, `value_after`, `uncosted_after` with the movement's `seq`; it is insert-only, written before the cost row, for the newest movement of (branch, item). `stock_costs` changes only to the newest value row's afters, continuing its befores (after − delta), so a second update or a change of one column alone is refused; it opens at zero. Every in leg needs its matched out leg (same source kind and id, leg `out`, kind `transfer_out` for `transfer_in` else the same kind, quantity −q, a batch of the same item, batch number and expiry) and that leg's value row; else 42501.
- **P2-2 (uncosted units, last cost):** costed units leave first: an outflow of q takes `least(q, quantity − uncosted)` costed units valued `round(value × costed_out / costed)` (the whole value when all costed units leave) and the rest from the uncosted units (value 0). The average is over costed units: `value / (quantity − uncosted)`; `last_unit_cost` stays null until a costed inflow and keeps its last value when no costed unit is left. An in leg takes exactly its out leg's value and uncosted units, so any pair leaves (quantity, value, uncosted) unchanged and 0 ≤ uncosted ≤ quantity after every movement. A receipt or count surplus without a cost is valued at `last_unit_cost`, or uncosted when there is none.
- **P3 (shape, bounds, input):** all three tables carry `id`, `tenant_id`, `branch_id`, `UNIQUE (tenant_id, id)`, composite FKs with ON DELETE RESTRICT; every numeric and money column is bounded with `between` (NaN rejected), quantities scale ≤ 4, `uncosted_quantity ≤ quantity`, value 0 when quantity 0. `stock_receive_costed` takes `unit_cost` as a JSON integer of 0–1,000,000,000 rupiah.
- **Backfill (point 4):** existing movements get value rows with value 0, all units uncosted, running afters per (branch, item) by `seq`; cost rows from the last after; guards created after the backfill.
- Open point 5 deferred (uncosted stock priced by the opening-data import, DATA-58); readers return no reason and no source id.
