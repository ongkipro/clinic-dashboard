## Design (proposed)

Principle: one shift per cashier per branch (BILL-18); every real payment a cashier receives is stamped with that cashier's open shift **at insert time by a trigger**, so no existing payment writer (`payment_receive`, `balance_top_up`, port settle, T-077 deposits) is re-created; the close freezes the expected amounts under the same `staff_access` lock that every payment insert already takes (`payments_guard`, 0091:1233), so no payment can slip into a closed shift.

### 1. Tables (migration: next free number, expected `0100_cash_shifts` after T-077–T-084; `src/modules/cashier/schema.ts`)
- **`cash_shifts`** (DATA-35, branch-scoped per `06:42`): `id`, `tenant_id`, `branch_id`, `cashier_id` (staff), `cashier_role` (owner|manager|fo_cashier|finance), `state` (`open` | `pending_approval` | `recount` | `closed`), `opening_float bigint ≥ 0` (Modal awal), `auto_opened boolean`, `open_key` (command key, unique per tenant), `opened_by/opened_as/opened_at`, `closed_at` (= first submit: the instant payments lock), `settled_at` (closed with zero variance or approved). Keys: `unique (tenant_id, id)`, `unique (tenant_id, branch_id, id)` (FK target), partial unique `(tenant_id, branch_id, cashier_id) where state = 'open'` (one open shift per cashier per branch). FKs to tenants, branches, staff. CHECK: `(state = 'open') = (closed_at is null)`, `(state = 'closed') = (settled_at is not null)`.
- **`cash_shift_counts`** (insert-only, one row per Tutup Kasir / Hitung Ulang): `id`, `tenant_id`, `branch_id`, `shift_id`, `seq` (1..n), `counted_cash bigint ≥ 0`, `expected_cash bigint`, `variance bigint` (generated `counted_cash − expected_cash`), `reason text` (3–500, required when variance ≠ 0), `threshold bigint` (SET-13 at the submit instant), `escalated boolean` (generated `abs(variance) > threshold`), `approval_id` (null iff variance = 0), `command_key` (unique), `counted_by/as/at`. Its decision state is read from `approvals` (no mutable column).
- **`cash_shift_count_lines`** (insert-only, the frozen expectation per tender): `count_id`, `method` (the 7 `PATIENT_PAYMENT_METHODS`), `payments` (int, number of payments), `received bigint` (Σ amount), `paid_out bigint` (cash only; 0 until the T-077/T-078/T-084 outflows, §3), `expected bigint` (cash: `opening_float + received − paid_out`; others: `received`), `counted bigint` (non-null only for `cash`). Integer rupiah, no cross-method sum stored.
- **`payments.shift_id uuid`** (nullable; DATA-72 "`cash_shifts` linked on payments"): FK `(tenant_id, branch_id, shift_id) → cash_shifts(tenant_id, branch_id, id)` (same branch guaranteed). Existing rows stay NULL (no backfill: no shift existed).
- Guards: `cash_shifts_guard` (BEFORE UPDATE/DELETE): no delete; only `open → pending_approval|closed`, `pending_approval → closed|recount`, `recount → pending_approval|closed`; identity columns immutable. `kasir_rows_insert_only` on counts and lines; `*_no_truncate` triggers; all `ENABLE ALWAYS`.

### 2. Stamping, opening, and tenders with no open shift
- **`payments_shift()`** new BEFORE INSERT trigger on `payments` (fires after `payments_guard` by name order, so after the lock): for a non-simulated payment with `charge_id IS NULL` it sets `NEW.shift_id` to the open shift of `(tenant, branch, received_by)`; if none is open it **auto-opens** one (`opening_float 0`, `auto_opened true`, audit `cash_shift_opened`). A caller-supplied `shift_id` is refused (`42501`). Simulated payments (BILL-29) get no shift. Port payments (`charge_id` set; settled possibly by an unbound webhook) get the creator's open shift if one is open at that branch, else NULL; they never auto-open and never land in a closed shift (open point 3).
- **`cash_shift_open(p_key, p_branch, p jsonb {opening_float})`** — Buka Kasir: `kasir_actor()`; branch = actor's branch (manager/FO) or `p_branch` (owner/finance); refuses when an open shift exists (`ERR_VERSION_CONFLICT: shift_open`); audit `cash_shift_opened`.
- **No open shift → tenders are not refused**; the first payment auto-opens (open point 1). This keeps T-072–T-084 writers and their tests untouched.

### 3. Expected amount per tender
`cash_shift_expected(p_tenant, p_shift)` (internal, STABLE) — the single place that knows the sources:
- **payments** with `shift_id = shift` (all real tenders, incl. Isi Saldo top-ups — `payments.invoice_id IS NULL` — and T-077 deposit receipts, which are payments with no invoice per the T-077 plan P1-3, so they are stamped automatically): Σ `amount` per `method` (cash `amount` is already net of change, CHECK 0087:46).
- **cash out (interfaces only, built by their tasks or added here if they land first):** T-077 clinic-cause cash refund of a booking DP (`deposit_refund_clinic`, method cash) and T-078 approved cash refunds (`refunds.destination = 'cash'`, state `paid`), and T-084 expenses funded from "cash" if that means the drawer (open point 5). Each such row must carry the payer's `shift_id` stamped the same way (a BEFORE INSERT trigger like `payments_shift`, refusing a non-open shift); `cash_shift_expected` sums them into `paid_out` for cash. At build time: grep the merged migrations for these tables and include exactly those that exist; if none exist, `paid_out = 0` and the function is the documented extension point.
- Cash expected = `opening_float + Σ cash received − Σ cash paid out`.

### 4. Counting: cash only; non-cash shown for reconciliation
- The cashier counts **cash only** (BILL-18 "any non-zero **cash** variance"); `counted_cash` required.
- EDC, transfer: expected and the list of payments with their references (`details.trace / approval_code / bank / reference`) to compare with the EDC settlement slip / bank mutation; QRIS, VA, link: "Dicocokkan Keuangan" (gateway clearing, `11:63`; settlement reconciliation is Finance, `19:46`, M8); Saldo: "Bukan uang laci". No count, no variance stored for non-cash (open point 2).

### 5. Submit, variance routing, decisions
- **`cash_shift_submit(p_key, p_shift, p jsonb {counted_cash, reason?})`** — Tutup Kasir / Hitung Ulang: `kasir_actor()` (staff_access lock first); actor = the shift's cashier, or a manager of the shift's branch (open point 4); shift locked `FOR UPDATE`; state must be `open` or `recount` (`pending_approval`/`closed` → `ERR_VERSION_CONFLICT: shift_pending|shift_closed`). Under the lock: expected computed, count + lines inserted, `threshold := setting_value_at('SET-13', branch, v_at)` (the same instant `v_at` everywhere; branch-scoped).
  - variance = 0 → shift `closed`, `settled_at`; no approval.
  - variance ≠ 0 → reason required (`ERR_INVALID_INPUT: reason`); `approval_request('cash_shift_variance', 'cash_shift', shift.id, reason, branch, abs(variance))`; shift `pending_approval`.
  - First submit sets `closed_at` (payments lock: from now the next payment of that cashier opens a new shift). Event `ShiftClosed {shift_id, count_id, variance: bool, escalated: bool}` on the first submit only (18:194; booleans and ids only, `events_payload_ok`). Audit `money_correction / cash_shift / cash_shift_counted` each submit.
- **Approval type** `cash_shift_variance`, label `Selisih kas`, requester roles `{fo_cashier, manager, owner, finance}`, approver roles `{owner, manager}`, `owner_self false`.

### 6. Payments locked after close
- A payment can only be stamped with an **open** shift (trigger chooses it; `payments_shift` re-checks `state = 'open'` and refuses otherwise); `cash_shifts_guard` forbids any transition back to `open`; payments, counts and lines are insert-only. So after `closed_at` nothing changes what the shift received; corrections are later refunds/adjustments in the then-open shift (never delete, AGENTS rule).
- Race: a payment and a close of the same cashier serialize on `staff_access` (both take it first); a payment committed before the close is in the expectation; one after it opens a new shift. Tested with two connections.

## Open points (with recommendation)

1. **Tenders when no shift is open.** Options: (a) refuse every real tender with `ERR_VERSION_CONFLICT: no_open_shift` until Buka Kasir; (b) auto-open a shift (modal awal Rp0) on the cashier's first payment. → **(b)**.
