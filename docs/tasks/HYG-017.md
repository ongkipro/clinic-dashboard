# HYG-017 — Test container durability and autovacuum (plan)

Owner decision 2026-11-14 ("oke ikuti rekomendasi", item 4; `/data/tmp/session-docs/open-for-owner.md`): the local test
container `clinic-dashboard-postgres-1` runs with `fsync=off` and autovacuum tuned for throwaway test databases. The autovacuum
item resolves to one PG 16 flag, `autovacuum_vacuum_cost_delay=0` (vacuum of `pg_shdepend` runs unthrottled, so its truncate lock
is held for less time); `autovacuum_vacuum_truncate` exists only from PostgreSQL 18 (§4 A) and autovacuum stays on. Build after
T-078 merges, one builder. Risk R2 (local developer infrastructure; no production, no CI workflow change).

## 1. Problem (evidence)

- HYG-016 close runs 1–3 (`docs/tasks/HYG-016.md` §"Close run 1/2", §"Close run 3 diagnosis"): test bodies and setups hit their
  limits while I/O pressure "full" was 30–73 %. The clinic container had written 720 GB in one session: every test file creates
  and migrates a fresh database (94 migrations) with `fsync=on`, `synchronous_commit=on`, `full_page_writes=on`.
- `tests/db/service-drift.test.ts:64` 55P03 (HYG-016 close run 3): an autovacuum truncate of `pg_shdepend` (a shared catalog every
  CREATE TABLE writes to) held AccessExclusive during a slow forced checkpoint (DROP DATABASE), and a fresh harness migration's
  `CREATE TABLE staff_roles` hit the runner's 5 s `lock_timeout`.
- Current settings (measured 2026-11-14 on the container): fsync on, synchronous_commit on, full_page_writes on, autovacuum on,
  naptime 60 s, shared_buffers 128 MB, max_connections 100, wal_level replica.

## 2. Design

**compose.yaml `postgres` service only** (the dev/test container; `postgres-backup` — the production image profile with WAL
archiving — is untouched). Add `command:` flags passed to the postgres entrypoint:

| Flag | Why |
|---|---|
| `-c fsync=off` | owner decision; throwaway test clusters; removes the per-commit and checkpoint flush I/O |
| `-c synchronous_commit=off` | with fsync off a commit still takes `WALWriteLock` and calls `XLogWrite()`; off hands WAL writes to the walwriter (Argon r1 P3-1) |
| `-c autovacuum_vacuum_cost_delay=0` | the owner's autovacuum item on PG 16 (default 2 ms, sighup): vacuum is not throttled, so a `pg_shdepend` truncation finishes sooner (Argon r1 P2-3, option 2) |
| `-c full_page_writes=off` | with fsync off a torn page cannot be prevented anyway; halves WAL after each checkpoint |
| `-c checkpoint_timeout=30min`, `-c max_wal_size=4GB` | fewer timed checkpoints during a 30-minute suite; DROP DATABASE still forces its own |

**A loud guard in the code that would otherwise trust it** — none needed: production and staging run on Coolify with their own
configuration (`docs/spec/15`); `compose.yaml`'s header already says "Local development database only (DEL-3)". Add one comment
line naming the owner decision and that the data in this container is disposable (a crash may lose it).

**Not changed:** `.github/workflows/*` (CI workflow changes are not authorized: DEC-082), `src/db/migrate.ts` timeouts
(production's), the harness, any test limit, `postgres-backup`.

**Applying it:** the running container must be recreated to take the flags (`docker compose up -d --no-deps --wait postgres`). The data volume
`pgdata` is kept (not a destructive operation: `clinic_dashboard`, `clinic_demo` and leftover `t065_exp_*` stay). Recreate only on
an idle host (no clinic heavy job), through `heavy-run --lock clinic-dashboard-env`.

## 4. Open points

- **A. (resolved, measured 2026-11-14: `pg_settings` on 16.15 has no `*vacuum_truncate*` GUC)** `autovacuum_vacuum_truncate` is a PostgreSQL 18 GUC; the container is 16.15. On 16 the equivalent is the per-table
  storage parameter `vacuum_truncate=false`, which PostgreSQL refuses on a system catalog (`pg_shdepend`) even for a superuser
  unless the postmaster runs with `allow_system_table_mods=on` (not used here).
  Decision (routine, inside the owner's "autovacuum tuning" scope): no truncate flag; keep fsync/synchronous_commit/full_page_writes/checkpoint flags — they
  shorten the forced checkpoint that made the truncation slow (the race's other half). Record the residual risk.
  Alternative (needs the owner): raise `autovacuum_naptime` or set `autovacuum=off` for the test container — off risks table
  bloat in long-lived `clinic_dashboard` dev data; not recommended.
- **B. Allowed paths:** `compose.yaml`, `docs/tasks/HYG-017.md`, `STATUS.md`, `BUILD-LOG.md`, `TASKS.md` (the HYG-017 row),
  `DECISIONS.md` (one DEC row), `ARCHITECTURE.md` (`## Operations`: one line on the local container flags; Argon r1 P3-2).
