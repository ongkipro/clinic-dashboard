## Design

**Migration `0063_visits.sql`** (drizzle DDL plus a rules section, as earlier tasks):
- Table `visits` (branch-scoped, DATA-17): `id`, `tenant_id`, `branch_id`, `patient_id`, `appointment_id` (nullable, unique per tenant: one visit per appointment), `kind` (`booked` | `walk_in`; walk-in writer is T-048), `checked_in_at`, `checked_in_by`, the nine independent state columns `intake`, `doctor`, `selection`, `consent`, `payment`, `preparation`, `treatment`, `dispensing` each in (`not_started`, `in_progress`, `done`, `not_needed`, `blocked`) default `not_started`, `closure` derived (`closed_at`, `closed_by`), `blocker` text (nullable, ≤ 120, set by later writers), `created_at`. Composite FKs to branch, patient, appointment (same tenant). One open visit per patient per branch (partial unique index where `closed_at is null`). The "Daftar" segment of VisitTrack = checked in (always done once the row exists).
- No `visit_states` history table yet: each later writer (BC intake T-051, doctor T-052, cashier T-072, room T-064, pharmacy T-065) updates its own column through its own definer; the audit chain and events carry the history (ids only). This keeps T-047 to what PR-7 needs; DATA-17's `visit_states` name is satisfied by the state columns (recorded in DEC-057, open point 1).
- Guard trigger: no delete, no truncate; identity columns immutable; `closed_at` set once; state columns change only through definers (a session flag set by the writers, as earlier guards).
- **Unpaid bills:** no invoice table exists before T-071/T-072. `payment` column: `not_started` until a bill exists; the cashier task sets `in_progress` (bill open, unpaid), `done` (settled) or `not_needed`. "Belum dibayar" = open visits with `payment` in (`in_progress`, `blocked`). The close blocker reads the same column. T-047's tests drive the column directly via the database owner to stand in for the cashier (scenario PR-7 "unpaid bill"), which the Done-when permits ("for an unpaid bill"); open point 2.
- Writers (SECURITY DEFINER, `tenant_actor_lock`, roles FO/cashier, manager, owner, admin pusat, `booking_branch` scope, `existing_appointment` capability, audit + event ids only, idempotency through `runCommand`):
  - `visit_check_in(p_appointment)`: the appointment must be booked or confirmed, today in branch time, not before `starts_at` − 2 h (early arrival) — open point 3; sets the appointment `arrived` (reservations kept: the slot is still used), inserts the visit, event `VisitCheckedIn`. Refusals: `not_today`, `not_scheduled`, `already_open` (patient has an open visit at the branch).
  - `visit_close(p_visit)`: refused with the blocker code when `payment` in (`in_progress`, `blocked`) → `unpaid_bill`, or `dispensing`/`treatment` = `in_progress` → `pending_dispensing` / `pending_treatment`; otherwise sets `closed_at`, releases the appointment's reservations, event `VisitClosed`.
- Reader `visits_today(p_branch)`: the branch's open visits plus today's closed ones (branch time), with patient name and MRN (no clinical content), and today's booked/confirmed appointments not yet checked in (for "Pasien Datang"). Readers: FO, manager, owner, admin pusat (+ the clinical roles later through their own screens; not here).
- RLS: `visits` readable by the scheduling readers of `appointments` (same role list, branch-allowed); `support_object_kinds` row `personal`; `clinic_operator` policy; `scope_map` row.

## Plan review r1 (Argon `52156219`: REVISE; the five open points accepted) and the revised design

- **P1-1** Writers check their own role list right after `tenant_actor_lock` (owner, admin pusat, manager, FO/cashier; central CS refused: it does not check patients in, 17:326) before any lock or `appointment_open`; the appointment goes to `arrived` with `state_changed_at` and `state_changed_by` (the 0062 state check); `checkIn` and `closeVisit` call `assertProductionGoLive` first (tested).
- **P1-2** `visit_close` locks the visit, checks scope, refuses `already_closed`, `unpaid_bill` (payment in progress or blocked), `pending_dispensing`, `pending_treatment` (in progress or blocked), releases the appointment's reservations, sets `closed_at` and `closed_by`. No session flag: `clinic_app` gets SELECT only; `visits_guard` (BEFORE INSERT/UPDATE/DELETE, always enabled, the staff-access lock) refuses delete; on insert requires open and, for a booked visit, its appointment arrived with the same patient and branch; on update keeps the identity columns, refuses a change to a closed visit and a close while a blocker holds. Constraints: `UNIQUE (tenant_id, id)`, `(tenant_id, branch_id, id)`, `(tenant_id, appointment_id)`, the open-visit partial unique index; composite restrict FKs to tenant, branch, patient, appointment and staff (checked in by, closed by); checks on kind ↔ appointment, closed_at ↔ closed_by, blocker length, the state values.
- **P1-3** `trackStates` always returns a blocker text when a step is blocked or a close blocker applies (the visit's own text, else the blocker's copy); the event payloads use `jsonb_strip_nulls` (no null values).
- **P2-1** isolation cases for `/hari-ini`, `/hari-ini/check-in`, `/hari-ini/papan` and the actions.
- **P2-2** refusal codes: `ERR_VERSION_CONFLICT: not_scheduled`, `ERR_INVALID_INPUT: not_today`, `ERR_INVALID_INPUT: too_early`, `ERR_VERSION_CONFLICT: already_open`; the reader returns `check_in_from` and the database time, and Pasien Datang is disabled before it with the time named. Filters: `semua` (Belum dibayar first when non-empty, Belum datang with `id="belum-datang"`, Kunjungan), `menunggu` (open visits and not-yet-arrived appointments), `belum-bayar` (open visits with payment in progress or blocked); a filter with no match on a day with rows shows the filtered-empty state with Hapus Filter.
