# Staging deployment (Coolify, KlinikMu Indonesia server)

Synthetic data only (MIG-2, DEC-034). `DEPLOY_ENV=staging` on the app and `platform_environment = 'staging'` in the database
keep the ARCH-10 real-patient gate exempt for synthetic runs only (DEC-125). Mock adapters for WhatsApp, SATUSEHAT, payments
and AutoLaris; no live provider call. Not a production definition.

## What runs

| Service | Image | Job |
|---|---|---|
| `postgres` | `postgres:16.15-bookworm` | database, default durability (unlike the local-dev `compose.yaml`, which runs `fsync=off`) |
| `migrate` | the app image plus `roles.sh` and `roles-entrypoint.sh` baked in | one-shot: `src/db/migrate.ts` as the owner role, then `roles.sh` (four login roles, `platform_environment`) |
| `app` | the repository `Dockerfile` | Next.js on port 3000; starts only after `migrate` exits 0 |

Not yet included: a scheduled worker (`src/workers/*` have no scheduler entry), so background jobs (outbox, export, booking
purge) do not run on their own; a pgBackRest sidecar for backups.

## Coolify settings

- Source: GitHub App, repository `ongkipro/clinic-dashboard`, branch `deploy-staging` (until this folder is merged to `main`).
- Build pack **Docker Compose**, base directory `/`, compose file `/deploy/staging/compose.yaml`.
- **Auto-deploy off.** Deploy a commit whose CI is green, by hand.
- Environment name `staging`.
- Build paths resolve from the repository root: Coolify runs compose with `--project-directory` at the checkout root,
  and turns relative bind mounts into empty directories, so nothing here is bind-mounted from the repository.
- Domains, all on service `app`, port 3000:
  `https://stg-app.klinikmu.com:3000`, `https://stg-vendor.klinikmu.com:3000`, `https://stg.klinikmu.id:3000`.

## Variables

Generated by Coolify from the compose file (no action): `SERVICE_PASSWORD_OWNER`, `SERVICE_PASSWORD_APPDB`,
`SERVICE_PASSWORD_AUTHDB`, `SERVICE_PASSWORD_VENDORDB`, `SERVICE_PASSWORD_OPERATORDB`, `SERVICE_BASE64_64_AUTH`,
`SERVICE_BASE64_64_AFTERCARE`, `SERVICE_BASE64_64_IMPORT`, `SERVICE_BASE64_64_PIXEL`, `SERVICE_BASE64_64_BOOKING`.

Optional, set in Coolify when needed: `TURNSTILE_SECRET_KEY` (booking OTP; outside production a missing key is allowed by the
code), `APP_RELEASE_DIGEST` (residency attestation), `RESIDENCY_*` (defaults: Biznet Gio / Jakarta / ID for all five kinds).

Never in Coolify: the KEK.

## One-time host preparation (KEK)

```sh
sudo install -d -m 0750 -o root -g 1000 /data/klinikmu/staging
umask 077; printf '1:%s\ncurrent=1\n' "$(openssl rand -base64 32)" | sudo tee /data/klinikmu/staging/kek >/dev/null
sudo chown 1000:1000 /data/klinikmu/staging/kek && sudo chmod 0400 /data/klinikmu/staging/kek
```

The app runs as uid 1000 (`node` in the image) and refuses a KEK file that is a symlink, not 0400/0600, or owned by another
user (`src/lib/keys/kek-file.ts`). Keep an offline copy of this file with the owner (ARCH-7): losing it makes encrypted fields
unreadable.

## After the first deploy

First platform owner (DEC-036), once, in the server terminal; the password is typed at a hidden prompt:

```sh
docker exec -it <migrate-or-app container built from this image> sh -c \
  'cd /app/migrate && DATABASE_URL=postgres://clinic_owner:<owner password>@postgres:5432/clinic_dashboard \
   node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON src/db/vendor-bootstrap.ts \
   --email <email> --nama "<nama>" --cidr <your IP>/32 --label "Kantor"'
```

Then sign in at `https://stg-vendor.klinikmu.com/vendor/masuk` and enrol TOTP.
