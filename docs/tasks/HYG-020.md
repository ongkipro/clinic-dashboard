## Why
`main` went red at `672d07f0` (T-097 integration): CI run 43779280032, job `verify`, step `Run pnpm test`, exit code 1 — one failure of
2511: `tests/cashier/consultation.test.ts:254` `expected [ 'ConsultationFeeRecharged', …(1) ] to deeply equal [ 'ConsultationFeeCharged', …(1) ]`.
- `consultation_recharge` (drizzle/0095_consultation.sql:674-693) writes both events in one transaction: `consultation_invoice_issue`
  (called at :683) inserts `ConsultationFeeCharged` (:361-363), then :688-691 inserts `ConsultationFeeRecharged`. Neither sets
  occurred_at or id: `occurred_at DEFAULT now()` (0019_domain_events.sql:10) is the transaction start, equal for both; `id DEFAULT
  uuid_generate_v7()` (0019:2; 0000_uuid_v7.sql) is a millisecond prefix plus random bits.
- The test's reader orders by `occurred_at, id` (consultation.test.ts:230), so two events of one transaction in the same millisecond
  order by random bits. Reproduced on a throwaway database: 400 transactions → occurred_at equal 400/400, Recharged sorted first 168/400.
- TD-50 (docs/spec/18:148) and DATA-59 (docs/spec/05:165) define no order among events of one transaction; consumers apply each event
  once (event_receipts). The test asserted an order the contract does not promise. Latent since T-079 (5480e5ca); not caused by T-097.
Evidence: /data/tmp/clinic-dashboard/ci-red/ (original CI log and metadata preserved; verify-order.sh; packets).
