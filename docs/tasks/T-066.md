## Open points (for the reviewer)

1. **Suppliers** (`suppliers`, tenant-shared, config): name (unique per tenant, case-insensitive), optional NPWP (15/16 digits), contact name, phone, email, address, payment terms in days (0–180), active. Writers `supplier_save` (create / update; never deleted; deactivate instead) by purchasing, admin pusat, owner. Readers: the stock readers (owner, admin pusat, finance, purchasing, auditor, manager, pharmacist).
2. **Which batch came from which supplier.** PR-75 "a batch received from a supplier". Today `stock_receive[_costed]` records no supplier. Proposal: a new costed receipt `supplier_receive(p_branch, p)` = `stock_receive_costed` + `supplier_id` (+ optional delivery note number), recorded in `supplier_receipts` (supplier, branch, batch, quantity, unit cost, source id = the receipt movement's source); T-067's goods receipts (GRNI, PO-matched) will write the same rows later. A return names the batch and the supplier; it is refused unless the supplier delivered that batch to the branch, and the returned quantity of a batch to a supplier never exceeds what that supplier delivered of it (net of earlier returns).
3. **Return** (`supplier_returns`, branch-scoped, personal): branch, depot (default the branch gudang; any active depot of the branch holding the batch), supplier, batch, quantity, reason code (`expired`, `near_expiry`, `damaged`, `recalled`, `wrong_item`, `quality`, `other`) + note (3–300), command key, by/as/at, the moving-average value at return time (from the movement's value row), credit expectation link. One `supplier_return` movement (`stock_move_depot`, kind `supplier_return`, source `supplier_return`/id). Unlike other outflows, **unfit stock may be returned** (expired, quarantined, temperature excursion, recalled — that is why it goes back): no `stock_assert_fit_depot`, only the depot holding (never negative) and an open vial of the batch in the depot is not returnable (refused: the opened part stays). Writer `supplier_return_record` by purchasing, pharmacist (at the active branch), manager (own branch), admin pusat / owner (named branch).
4. **Credit expectation** (`supplier_credit_expectations`, tenant-ledger, money_total): one per return; amount = the movement's moving-average value (integer rupiah, from `stock_movement_values.value`, positive); state `expected` → `received` (credit note recorded, T-067) | `written_off` (finance, with reason) — only `expected` is created here; transitions are T-067's (state check allows them). An uncosted return (value 0) still creates the expectation with amount 0 and `uncosted = true` so finance sees it.
5. **Events**: `SupplierReturned {return_id, supplier_id, batch_id, expectation_id}` (ids only). Audit row per write.
6. **Readers**: `supplier_list()`, `supplier_get(id)` (with its receipts and returns per branch the reader may see), `supplier_return_list(p_branch)` (stock readers; money columns only for `stock_cost_readable`), `supplier_batches(p_supplier, p_branch)` (returnable quantity per batch). No UI (T-067).
7. **Scope**: tables in `src/modules/purchasing/schema.ts`; module `src/modules/purchasing/suppliers/suppliers.ts`; tests `tests/purchasing/returns.test.ts`; expected expansions `tests/rls/rls.test.ts`, `tests/rls/authority-clock.test.ts`, an isolation case for the module's server actions? (none: no actions or routes — the module is exercised by tests only; the isolation gate covers routes/actions/jobs/exports, so no case is needed).

## Plan review (Argon `b8e68043`, APPROVE PLAN) — findings checked against the code and adopted

1. **P2 order and links.** The valuation trigger (0080:206) is AFTER INSERT FOR EACH ROW, so the value row exists when `stock_move_depot` returns: `supplier_return_record` pre-generates the return id, moves first (source `supplier_return`/id), reads `stock_movement_values`, then inserts the return (movement id, value, uncosted quantity) and the expectation. The link is one-way: `supplier_credit_expectations.return_id` (unique, composite FK); `supplier_returns` carries an optional `credit_note_ref` (DATA-54) instead of an expectation id. Insert guards assert the movement and value rows match the return, the returned total per (branch, supplier, batch) ≤ delivered, and the expectation's amount and `uncosted` match the return.
2. **P2 money columns.** Column-level SELECT grants (as `stock_count_lines`, 0077:458): `supplier_receipts.unit_cost` and `supplier_returns.value` not granted to `clinic_app` / `clinic_operator`; expectations read through `stock_cost_readable`. `supplier_get` and `supplier_return_list` return money fields only when `stock_cost_readable` for the row's branch.
3. **P2 T-067 reuse.** `supplier_receive` (pharmacist, purchasing; as `stock_receive_costed`) over an internal `supplier_receive_into(tenant, staff, role, branch, supplier, p, source_kind, source, key)` that writes `stock_receipt_costs` and `stock_receive_into` under ('supplier_receipt', its own id) and the `supplier_receipts` row (`source_kind` `supplier_receipt` with a command key, or `goods_receipt` for T-067's lines without one). Expectations carry their T-067 resolution columns now (`credit_note_id`, `closed_reason`, `closed_by`/`as`/`at`; state expected → received | written_off once).
4. **P3 coverage.** `temperature_excursion` (0082) in the return tests; a return from a non-default active depot; an inactive depot refused; the open vial's remainder stays (`quantity ≤ holding − open vial remaining`, as `transfer_take_lines` 0078:709); every numeric bounded with `between`; drift test `tests/db/suppliers-drift.test.ts` (no 0000–0082 function or policy changed).

Roles (decided): `supplier_save` purchasing, admin pusat, owner; `supplier_receive` pharmacist, purchasing; `supplier_return_record` purchasing, pharmacist, manager (own branch), admin pusat, owner (named branch). No isolation case: the module has no route, action, job or export (as T-063).
