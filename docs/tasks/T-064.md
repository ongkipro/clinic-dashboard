## Plan review round 1 (Argon `ad50677d`): REVISE PLAN → adopted

Verified against the code: `material_issues` and `material_consumptions` are unique per request (0079:61, :29), so a request added during treatment is a separate request; `stock_item_readable` / `stock_readable` exclude room roles (0077:202-204), so the room cannot list items or depots through T-060/T-061 readers; `treatment_start_check` requires one plan, a performer, and writes an audit row per call (0073:545-558, :594); `visits.blocker` is 1–120 characters (0063:27); `visits.ts` maps errors outside `runCommand`.

- **P1-1 (materials across requests):** `treatment_start` may link an issued, unconsumed request of the visit whose plan item is null or the execution's; "Bahan Tambahan" creates a request with the execution's plan item. `treatment_finish` takes every non-cancelled request of the visit with that plan item or the linked one (not linked to another execution), refuses while any is still `open` (`ERR_VERSION_CONFLICT`), and calls `material_consume` for each issued, unconsumed one in the same transaction with a key derived from the finish key and the request id (sha-256 hex), passing that request's deviation lines; an already reconciled request is skipped.
- **P1-2 (once per item per visit):** `UNIQUE (tenant_id, visit_id, plan_item_id)` unconditionally; a free reschedule happens on a later visit.
- **P1-3 (room data):** `treatment_get(visit)` (definer) also returns the active ruang depots of the branch, the active stock items (code, name, unit, class) and the open vials of the visit's requests' batches in ruang depots (remaining, use-by). No 0077–0080 function changes.
- **P2-1 (gate and lists):** `treatment_start` keeps `treatment_start_check(visit, [item], performer, supervisor)` plus a payment check (`payment` not `in_progress`/`blocked`, else `payment_unpaid`) and raises `ERR_START_BLOCKED` with the blocker list. `treatment_get` writes one `treatment_viewed` audit row and computes per item the blockers without a performer (payment, examination, contraindication, consent) and the eligible performers and doctor supervisors with the 0073 helpers. `treatment_room_list` lists open visits and visits closed today at the branch with a live plan item of an active plan of the patient's cluster or an execution, blocked ones included, room from the execution or else the appointment's treatment-room reservation.
- **P2-2 (timer):** `paused_at` (set iff paused); resume shifts `stage_started_at` by the pause; stages strictly forward (preparation → anesthesia → procedure → recovery) and only while started; finish from started or paused; readers return the database `now`.
- **P2-3 (people, room, keys):** optional assistant (≠ performer, a doctor/nurse/therapist role at the branch); a supervisor when given is a credentialed doctor of the branch ≠ performer whatever the delegation mode; a room when given is an active treatment room of the branch (defaulting from the linked request's room depot); every transition has a command key unique per tenant on its event row, plus the start and finish keys on the execution.
- **P3-1 (scope, errors):** scope map `branch-scoped` (module treatment, readers doctor, nurse, therapist), support class `clinical`; writers and readers take `tenant_actor_lock()` first; the module maps errors outside `runCommand` (as `visits.ts`).
- **Decisions:** payment `not_started` accepted until the cashier task (T-072) tightens it — DEC-074; the contract for T-076/M5: `counted` and `TreatmentFinished {execution_id, visit_id, plan_item_id, outcome, counted, performer_id}`; Logbook stays with T-068; no spec change.
