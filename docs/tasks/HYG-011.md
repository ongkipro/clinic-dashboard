# HYG-011 — Measured limits for timing-bound tests

Status: PLANNED · Risk: R2 (tests only) · Owner decision DEC-041 (2).

## Why

HYG-006's final evidence run failed one test in suite 3 of 3: `tests/events/events.test.ts › workers and consumers (TEN-5) › four workers draining 200 events apply each exactly once`. It timed out at the default 5 s; its normal duration is 2.1–3.2 s. The run was slow throughout: 72.9 s against 43 s, with checkpoints writing for up to 6.6 s. Other work was loading the host disk.

A limit only 1.6–2.4× a test's normal duration fails under ordinary load on the local SSD.

## Change (to plan in full)

- From the JSON reporter of several full suites (`--reporter=json`), list every test whose p99 duration is above 40 % of its limit.
- Give each one an explicit, measured limit with a comment naming its normal duration: `{ timeout: … }` per test or per describe, following `tests/vendor/onboarding.test.ts` and `tests/vendor/support.test.ts`. No global change: `vitest.config.mts` stays as HYG-004 left it.
- Where a test can be made cheaper without losing what it proves (for example fewer events with the same concurrency), prefer that.

## Done when

- The list and the chosen limits are recorded with their measurements.
- Full suite ×3 under the host rule. Any failure is recorded, never re-run until green.
- Independent review.
