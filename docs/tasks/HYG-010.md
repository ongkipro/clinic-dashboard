## Findings to fix

### N-1 — HIGH: the isolation gate cannot fail for cross-tenant writes made by Server Actions

For `action` and `job` cases, the negative run only checks that no tenant-B secret appears (`tests/isolation/isolation.test.ts:170–180`). A cross-tenant write that succeeds and returns `"done"` therefore passes:

- `staff.cases.ts:89, 141–149, 163`;
- `settings.cases.ts:91–96`: the positive control has already consumed the draft;
- `approvals.cases.ts:91–101`.

Fix:
- Action and job negatives must return an explicit refusal.
- Consumable victim state is re-seeded for the negative run.
- A success is returned as a secret-bearing body.

### C-02 — MEDIUM: the outbox job's negative run processes no event

`tests/isolation/cases/events.cases.ts:10–44` seeds its victim event only once, so the negative phase claims nothing.

Fix: seed a fresh event for each run, and assert that the handler ran.

### N-3 — MEDIUM: `/staf/[id]` is a by-id route declared `filtered`

The TEN-1 404 is never asserted (`staff.cases.ts:107–120`).

Fix: declare it `not-found` and return 404 when the id is not found.

### C-01 — MEDIUM: browser runners exit 0 after a failed flow

Every `tests/ui/*.spec.ts` runner, and `auth-screens.mjs`, catches its error into `report.error`.

Fix: keep the report, and set `process.exitCode = 1`.

### C-03, N-4 — LOW: stale current-state lines

- `STATUS.md`: "Built so far" stops at DEC-015; "No clinic page exists yet"; "/audit reads tenant and role from the query string"; the `role_assign` lock follow-up.
- `ARCHITECTURE.md`: counts and migrations (partly updated 2026-11-05).

Fix: correct or delete them.

### N-5 — LOW: superseded decision parts are not marked

DEC-031 D1 replaces part of DEC-024, and D7 changes part of DEC-015.

Fix: add "Supersedes" to DEC-031 and a note on both old rows.
