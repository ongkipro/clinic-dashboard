## Design (proposed)

**Data** (migration 0057, DATA-11, DATA-46):
- `branches` gains:
  - `address` (exists);
  - `map_url` (https only);
  - `whatsapp_number` (E.164 `+62…`, optional);
  - `licence_number`, `nib` (13 digits), `facility_code`, `satusehat_org_id` (SET-46);
  - `responsible_staff_id`, an FK to `staff` in the tenant (the Penanggung Jawab);
  - `publish_from` and `publish_until` (timestamptz; until > from).
- `branch_hours`: weekday 0–6, `opens`, `closes` (time, opens < closes, several intervals per day allowed, no overlap). A row change replaces the whole weekly set in one function call, and the change is audited.
- `branch_closures`: a date, an optional time range (null = all day), and a reason. Each is a single row, added or removed before the date passes; past closures are kept.
- `rooms` (DATA-46): name, kind (the existing `ROOM_KINDS`), `satusehat_location_id`, and an active flag. Rooms are deactivated, never deleted.
- `branch_devices`: device type (the existing `DEVICE_TYPES`), label, and an active flag. DATA-46 names only rooms; devices are added because T-034 service requirements name device types and T-044 needs the count per branch.
- `branch_services`: branch × catalog item (services only) — "Layanan Tersedia". An explicit list, empty by default; empty means nothing is offered at the branch until set.

Every table is tenant-keyed with composite FKs (ON DELETE RESTRICT), has RLS readable by every member of the tenant (branch data is operational, not personal), a `scope_map` row, and a vendor support class `config` with one operator policy (TEN-19).

**Writes** (SECURITY DEFINER under `tenant_actor_lock`, audited `settings_change`, event `BranchChanged` with ids only):
- `branch_update_profile(branch, fields)`: identity, contacts, location, publish window, licence data. Owner and Admin Pusat (IAM-11, SET-46).
- `branch_set_hours(branch, weekly, reason)`, `branch_closure_add` and `branch_closure_remove`: Owner, Admin Pusat, and the manager for a branch in their own branch set (SET-2).
- `room_upsert`, `room_set_active`, `device_upsert`, `device_set_active`: Owner, Admin Pusat, and the manager for their own branch (19:69).
- `branch_set_services(branch, items)`: Owner and Admin Pusat.

**UI:**
- `/pengaturan/cabang` lists the branches.
- `/pengaturan/cabang/[id]` is the UX-2 form, with sections Identitas, Jam Buka, Libur, Ruang & Alat, Layanan Tersedia, WhatsApp, Lokasi & Peta, Situs, Izin (SET-46). Each section has its own Simpan; controls appear only for roles that may change that section. The manager sees their own branch, and only Jam, Libur and Ruang & Alat are editable for them.
- `/pengaturan/cabang/jam` and `/pengaturan/cabang/ruang` (existing nav entries) redirect to the selected branch's section.

**Readers for later tasks:**
- `branch_is_open(branch, at)` for T-044 slot finding. It evaluates the weekly hours and the closures in the branch timezone.
- Rooms and devices for booking, by branch.

## Open points for the plan review

1. **Who adds a branch.** PR-2 says "the owner shall manage branches", and IAM-11 gives Admin Pusat the branches. Today a branch is created only by tenant provisioning; adding branches is not in the T-036 Done-when. Proposal: T-036 edits existing branches only. Adding a branch goes through the vendor or onboarding path later (it changes the checklist and billing, PR-61), so it should get a decision row when a task needs it.
2. **Hours authority conflict.** SET-2 lets the manager change hours for their own branch; UX-2 says "manager (view own)". Proposal: follow SET-2 and 19:69 for Jam, Libur and Ruang & Alat, which are operational. Identity, licence, services, WhatsApp, map and publish window stay with Owner and Admin Pusat, as in UX-2.
3. **SET-46 "required before clinical go-live".** T-027's go-live gate today checks the `satusehat` checklist item at tenant level. Proposal: the branch page shows the missing licence fields with the UX-2 blocked copy. Whether go-live also requires SET-46 per branch is a gate change for T-027's function and not in T-036's paths, so it is flagged and not built here.
4. **Services offered default.** Proposal: an empty list means "not yet configured", and the page says so. T-044 then offers no slot. The alternative is "every active service", which would silently offer services a branch cannot perform.
