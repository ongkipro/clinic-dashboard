## Design (proposed, option A)

**States and transitions** (DATA-16, PR-83):
- `held → booked` (T-044, `booking_confirm`), `held → cancelled` (released hold), `booked → confirmed` (reminder reply or FO), `booked|confirmed → cancelled` (Batalkan, reason), `booked|confirmed → no_show` (Tandai Tidak Datang, only at or after `starts_at` + SET-15 when set), `booked|confirmed → rescheduled` (Ubah Jadwal: the old row becomes `rescheduled` with `rescheduled_to`, a new appointment is created through the same slot rules, in one transaction), `booked|confirmed → arrived` (T-047 check-in; not built here).
- Leaving `held/booked/confirmed` for `cancelled`, `no_show` or `rescheduled` releases the reservations (active → false). A cancelled or no-show appointment is never reopened.
- New columns: `state_reason` (cancel reason, 3–500 chars), `state_changed_at`, `state_changed_by`, `rescheduled_to` (FK to the new appointment).
- DP effects (PR-22 forfeit, balance) are M4; T-045 moves no money (the Done-when).

**Writers** (definer, `tenant_actor_lock`, `booking_branch` scope, roles FO/cashier, Central CS, Manager, Owner, Admin Pusat; audit; events `AppointmentCancelled`, `AppointmentNoShow`, `AppointmentRescheduled` with ids and codes only; TS through `runCommand` with errors mapped outside):
- `appointment_confirm(id)`; `appointment_cancel(id, reason)`; `appointment_no_show(id)` (refused before start + lateness); `appointment_reschedule(id, start, staff?)` (creates the new booking with `booking_create`'s pick and the old version's service; the patient-overlap rule ignores the row being moved).

**Reader:** `appointments_window(branch, from, to)` for the calendar: rows with patient name, service name, performer, room and device labels, state; RLS-bound (booking roles at the branch).

**UI** `/jadwal`: Hari Ini (day list per performer / room / device; the phone agenda at compact widths) and Minggu (week grid at regular widths); filter by doctor, room or device; state chips with words; row actions Ubah Jadwal (sheet with `booking_slots` for that service and date), Batalkan (reason; "Aturan DP berlaku saat modul kasir aktif" until M4), Tandai Tidak Datang (enabled after start + SET-15); Buat Janji links to the booking sheet (the full Reservasi Baru sheet with patient search is the next UI step; T-045 offers create from a patient id chosen in Pasien → later). Read-only for BC and clinicians.
