## Why
Two pre-existing fixtures failed T-085's close runs at night (evidence `/data/tmp/clinic-dashboard/t085/failure-close2/`, `failure-close3/`):
- `tests/cashier/deposits.test.ts:128` `soon(i)` clamps every arrival slot to next WIB midnight − 30 min, so from about 22:15 to 24:00 WIB
  `soon(1)` and `soon(2)` overlap for one doctor and room → `resource_reservations_no_overlap`.
- `tests/cashier/consultation.test.ts:44` `day(d)` is the UTC date; `control_schedule` (0095) compares with the branch-local date, so from
  00:00 to 07:00 WIB `day(0)` is yesterday → `ERR_INVALID_INPUT: control_date`.
The same UTC `day()` helper is defined in 14 test files (`grep 'const day = (d: number) => new Date(Date.now() + d \* 86_400_000).toISOString()'`);
each is a candidate for the same night failure wherever the date is compared with a branch-local day.

## Change (tests only; no product code)
1. One shared helper `tests/support/dates.ts`: `wibDay(d)` = the Asia/Jakarta calendar date d days from now (`Intl.DateTimeFormat("en-CA",
   { timeZone: "Asia/Jakarta" })`), the branch timezone of every fixture tenant.
2. Replace the UTC `day()` in all 14 files by `wibDay` (one line each: `const day = wibDay;`). Every use is a calendar date sent to a writer
   (expiry, business date, control date, credential dates) that the database compares with the branch-local day, and every fixture's first
   branch is Asia/Jakarta (four files also have an Asia/Makassar branch; WITA is one hour ahead, so the Jakarta date is never a day ahead
   of it — the old UTC date could be).
3. `deposits.test.ts` `soon(i)` = `arrivalSlot(i, 3)`: three distinct 30-minute slots of today that end by WIB midnight (counted back
   from the last one when fewer fit after the next quarter hour).
4. `tests/support/dates.test.ts`: the helpers at 22:30:37, 23:50, 00:05 and 06:55 WIB (an explicit `now` argument, no global fake clock).
