## Open points (for the reviewer)

1. **Selection (DATA-20 subset).** `selections` (visit, patient, guiding BC, closing staff, confirmed_at/by/as, patient agreement ref nullable — the signature capture is UX-7's panel, open) and `selection_items` (plan item **or** product catalog version, qty). Writer `selection_confirm(visit, items)` by BC, doctor or FO at the active branch; one confirmed selection per visit (a later change is a new version, out of scope); sets `visits.selection = 'done'`; emits `ItemsSelected` (ids). Prices and payment are the cashier's (M4).
2. **Recipe → stock map.** `pharmacy_recipe_items` (catalog version, recipe row index, stock item, qty per treatment in the stock item's unit), maintained by the pharmacist; the catalog's free-text row stays untouched. A recipe row without a mapping appears on the list as "belum dipetakan" (manual pick), so nothing is silently dropped.
3. **Automatic prep list (PR-18).** On `selection_confirm`, per selected treatment: one `material_request` (T-062) for the visit and plan item with the mapped recipe lines × qty into the room depot of the branch's default ruang (or none if no ruang depot: flagged); per selected product: one `dispensings` row `queued` (apotek). `visits.preparation = 'in_progress'`. The Siapkan list shows both (material requests to issue through T-062's `material_issue`; product dispensings to prepare).
4. **Prescription (DATA-26).** `prescriptions` (visit, patient, prescriber doctor, state draft | signed | void, signed_at, valid_until = signed + 30 days) and `prescription_items` (product catalog version, KFA code optional, dose/route/frequency/duration text, qty, external-use flag). Writers `prescription_create`, `prescription_item_add/remove`, `prescription_sign` (doctor, step-up proof as T-053), all in `src/modules/pharmacy`. Signing creates `queued` dispensing lines for its items. Special drugs: a catalog item flagged narcotic/psychotropic cannot be prescribed or dispensed — no such flag exists in the catalog; proposal: refuse items whose KFA code is in a fixed narcotic/psychotropic prefix list? Recommendation: add `pharmacy_special_items` (pharmacist-maintained block list) and refuse those.
5. **Dispensing (CLIN-017/018).** `dispensings` (visit, prescription?, selection?, state queued | prepared | handed | cancelled, queued_at, prepared_at/by, handed_at/by, command key) and `dispensing_lines` (product, batch, qty). `dispense_prepare` (pharmacist: FEFO in the apotek depot, fit stock only — `stock_assert_fit_depot`; **no stock moves**: CLIN-017), `dispense_hand_over` (the seven checks all recorded true or with an exception note; `stock_move_depot` kind `dispense` per line; `handed`; once per dispensing — a retry replays: CLIN-018; `MedicationDispensed` / `ProductHandedOver` events with ids). `visits.dispensing`: `in_progress` while any dispensing of the visit is queued or prepared, `done` when all handed or cancelled (CLIN-025 through `visits_guard`).
6. **Batch states.** Add `temperature_excursion` to `stock_batches` (non-dispensable like quarantine; release to active by the pharmacist with a reason, also from quarantine). This re-creates `stock_batch_hold`, `stock_unfit_reason`, `stock_batches_guard` (0077) and widens the state check: a drift test (`tests/db/pharmacy-drift.test.ts`) declares exactly those.
7. **Recall trace.** `pharmacy_recall_trace(batch)`: dispensings and patients that received the batch (pharmacist, manager).
8. **Labels.** `labels` (dispensing line, kind internal | external_use (etiket biru), printed_at/by, reprint count); the UI prints through the browser (`window.print` of a label view); no printer integration.
9. **CLIN-024.** The Serahkan screen's "Tandai Keluhan Klinis" calls T-057's `complaint_flag` (source pharmacist) — no new SQL.
10. **Who and what is seen.** Pharmacist writes (prepare, hand over, labels, recipe map, special list) at the active branch; doctor writes prescriptions; BC/doctor/FO confirm selections. Readers: pharmacist and doctor full; FO the dispensing status only (UX-10 "FO sees status only" — through the VisitTrack `dispensing` step, no new reader). RLS `pharmacy_readable`; scope map; support class clinical (prescriptions, dispensings) / personal (selections); events ids only.

The Siapkan list is a reader that computes each selected treatment's materials from the recipe map × selected qty (PR-18 "without manual entry" holds: nothing is typed). The pharmacist's **Siapkan** on a treatment row calls a pharmacy writer that creates the T-062 material request as the pharmacist (an allowed requester), with a key derived from the selection item, into the room depot resolved as: the depot of the room reserved for the visit's appointment (0081 pattern), else the branch's first active `ruang` depot by `created_at, id`; none → the row is blocked "Depot ruang belum diatur". Then T-062's `material_issue` issues it. 0079 is untouched. Selection items store `plan_item_id` (nullable) and `catalog_version_id` (not null; from the plan item when given), go through `catalog_version_reference`, and branch on the catalog kind: service → treatment materials; product → a `queued` dispensing; package → refused (M4).
2. **P1-2 adopted.** `stock_batch_hold` order: state valid → `recalled` or same state → VERSION_CONFLICT → reason 3–300 required for every transition (also release). History kept in an insert-only `stock_batch_holds` (batch, from, to, reason, by, as, at); the batch row keeps its current hold columns. `temperature_excursion` ("Suhu menyimpang") added to `BATCH_STATES` and `/stok` labels (scope expansions `src/modules/inventory/schema.ts`, `src/app/(app)/stok/labels.ts`). `items.test.ts` stays green.
3. **P1-3 adopted.** `dispensings.depot_id`: chosen at prepare from an active `apotek` or `gudang` depot of the branch (default: the first active `apotek` depot holding fit stock of the item, else `depot_default`). FEFO picks aggregated per batch (`dispensing_lines` unique per dispensing and batch); a pharmacist override batch must pass `stock_assert_fit_depot`. Handover locks actor → visit → dispensing → batches by id, re-asserts fitness per line, runs `material_vial_take` for open vials, then `stock_move_depot` kind `dispense`.
4. **P2-1 adopted.** `prescriptions.is_acute`, `set48_snapshot`; `valid_until` from `setting_value_at('SET-48', NULL, now)` (`masa` or `masa_akut`); prepare and handover refuse an expired prescription.
