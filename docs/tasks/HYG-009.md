# HYG-009 — Clinic write actions: refuse a stale context; staff detail, branch settings and context switch fixes

Status: PLANNED (plan not yet written in full; findings verified) · Risk: R3 (tenancy, authorization)
Owner instruction: 2026-11-05, "review keseluruhan fondasi … jika ada bugs dan kekurangan kamu sempurnakan". Decisions are revisable defaults (DEC-041).

## Findings to fix

### B2-1 — HIGH: a form shown for one clinic writes into the clinic selected now

Server Actions resolve the **current** `clinic_context` cookie, not the context the form was rendered in, and tabs share one cookie. So the input of these actions can be applied in another clinic:

- **Write into the wrong clinic:**
  - `src/app/(app)/pengaturan/actions.ts:52–60` `saveAction`;
  - `src/app/(app)/kepatuhan/actions.ts:56–58` `uploadAction`, which also reopens an approved item in the other clinic;
  - `src/modules/org/staff/actions.ts:44` `inviteAction`.
- **Bind the wrong context but fail closed:**
  - `pengaturan` `withdrawAction`;
  - `persetujuan` `decideAction`;
  - `kepatuhan` `decideAction`;
  - the staff actions (cancel invite, revoke session, end membership, remove role, duty);
  - `answerOwnerGrantAction`;
  - `switchAction`.
- **Within one clinic,** a role or branch switched in another tab changes the acting role of every action above.

Fix: every clinic write action posts the rendered tenant, acting role and active branch, and compares them with the freshly resolved context before the mutation. On a mismatch it refuses with a "the page changed, reload" message. The posted fields are an expectation, never authority. A two-tab regression test covers each of the writing actions.

### N1 — MEDIUM: `/staf/<id>` crashes when Admin Pusat opens a privileged staff member

`src/modules/org/staff/page-data.ts:64` calls `staffSessions`, which raises `ERR_NOT_FOUND` for staff Admin Pusat may not touch (`drizzle/0026_staff_access_rules.sql:509–510`). Nothing catches it, and there is no `error.tsx`.

Fix: list sessions and show the manage buttons only for staff the viewer may touch. Add a test.

### N2 — LOW: an Owner with a branch selected cannot save branch settings except at that branch

The UI offers "Semua cabang" and every branch (`pengaturan/data.ts:51–54`). `setting_set` refuses them when `app.active_branch_id` is set (`drizzle/0028_settings_rules.sql:349–354`). This contradicts DEC-026 ("The owner changes every row").

Fix: apply the branch checks only to Level 3 roles. Add a test with an Owner bound to a branch.

### N3 — LOW: a revoked session can still write `org_actions` into the revoked clinic

`switchContext` calls `activeContext` without the session id (`src/modules/org/context/context.ts:149, 164`).

Fix: pass the session id. Add a test: revoke for clinic A, switch to A, expect `ContextSwitchError` and no row.

## Not a defect (recorded)

- **B2-2:** settings mutations carry no idempotency key. AGENTS.md scopes idempotency to money, stock, session and commission commands, and API-2 (`docs/spec/09`) is a Proposal. If a decision extends it, it becomes its own task.
