## 1. Reporting unit, context and lifecycle (r1 P1-4)
- The reporting unit is the **visit with a signed examination**. An outbox item is created **when the record is signed** (so the monitor
  shows it pending at once — Scenario PR-35) by an AFTER INSERT trigger on `record_versions` (version 1) that only inserts rows (no external
  check, no lookup that can fail on SATUSEHAT state; an ordinary DB error still rolls back as any write). The item is **not due before the
  visit closes**: Encounter.statusHistory needs arrived, in-progress and finished (Q-19 Encounter), so sending waits for `visits.closed_at`.
- **Context snapshot at signing** (`satusehat_visit_context`, one row per visit, immutable): branch, patient, signing doctor, the consultation
  room = `queue_tickets.room_id` **as it is at signing** (later re-calls do not change it; review r1 P1-4), arrived_at =
  `visits.checked_in_at`, in_progress_at = `examinations.created_at` (the doctor opened the examination). finished_at = `visits.closed_at`,
  read at send (immutable once set). A visit signed without a called room → context with room null → the item is held
  `facility_context:no_room` (resolvable only by a records officer choosing an active room of that branch; audited).
- **Revisions**: an item = (visit, revision). Revision 1 at signing; a correction (`record_versions` kind correction) adds revision n+1
  pinned to that version id. The worker builds every resource of a revision from **its pinned examination version** and from source rows
  that are immutable in the states used (counted, finished treatment executions; signed prescriptions; handed dispensings). A newer revision
  supersedes not-yet-started older ones; one that is in flight finishes its lease (§3) and its links are then re-sent at the new revision.

## 3. Outbox, lease and fenced completion (r1 P1-2)
- `satusehat_outbox(tenant, branch, visit, revision, exam_version_id, state queued|held|leased|done|superseded, hold_reason, lease_gen,
  lease_until, attempts, next_at, created_at)`; at most **one leased item per visit** (partial unique index); claim (unbound worker,
  `FOR UPDATE SKIP LOCKED`) takes due items of visits with no live lease, bumps `lease_gen`, sets `lease_until = now + 5 min`.
- **Uncertainty barrier per remote resource (r2 P1-1)**: a link whose last write (create or update) is `outcome_unknown` blocks every newer
  write to that link — a lease expiry hands over only the right to *reconcile*, never to write. The HTTP client aborts a request after 30 s;
  the lease is 5 min. The provider documents no remote concurrency control (no If-Match / versionId on the pages read — Q-19), so an
  unresolved write stays a blocking manual exception, never overtaken automatically.
- Every remote call is bracketed by **fenced** definers taking `(item, lease_gen)`: `satusehat_mark_sending(item, gen, link)` before the HTTP
  call (link → `sending`), `satusehat_record(item, gen, link, outcome jsonb)` after. A stale gen (lease expired and re-claimed, or superseded)
  is refused for state changes, but a reported remote id is still **recorded as an attempt** and the link set to `outcome_unknown` (never
  dropped, never overwriting a newer confirmed state).
- **Crash recovery**: at claim, an item whose lease expired with links in `sending` → those links `outcome_unknown` (crash after a possible
  remote commit) before anything else is sent.
- Signing's trigger stays insert-only; stale work is handled in the worker.

## 4. Sync ledger (TD-32, r1 P2-8) and transitions (r1 P2-7)
- `satusehat_links(tenant, branch, environment, fhir_type, visit, local_key, remote_id, status, current_revision, updated_at)`, unique
  (tenant, environment, fhir_type, visit, local_key).
- `satusehat_attempts` (append-only, never updated/deleted): link, revision, exam_version_id, lease_gen, verb create|update|search, outcome
  ok|http_4xx|http_5xx|timeout|lost|stale, http status, remote_id, remote_version (meta.versionId when returned), error code, path, at.
- Link transitions (guarded; anything else refused):
  | from | to | when |
  |---|---|---|
  | queued | held | a send-time prerequisite fails (identity, practitioner, mapping, context, credentials, organization changed) |
  | held | queued | the hold cause is resolved |
  | queued | sending | fenced mark (barrier clear) |
  | sending | confirmed | 2xx |
  | sending | queued (next_at) | 5xx / network before exhaustion (retry; attempt kept) |
  | sending | failed | 4xx, or 5xx retries exhausted |
  | sending | outcome_unknown | timeout, lost response, crash recovery |
  | outcome_unknown | confirmed / queued(check_again) / exception | §5 (create and update rules differ) |
  | confirmed | queued (update at revision n+1) | amendment with a changed fingerprint (unchanged → nothing sent) |
  | confirmed | withdrawal_pending | the source disappeared in a correction (no guide rule for withdrawal) |
  | failed / exception / withdrawal_pending | queued | **Kirim Ulang** (authorized roles, reason; idempotent; audited; a new attempt) |
- Outbox item (one delivery unit for one visit revision): queued → leased; leased → queued (lease released with work left: retries,
  reconciliations); leased → done when no link of that revision is queued, sending or outcome_unknown; queued → superseded (a newer revision
  before any lease); done and superseded are final. Hold resolution and **Kirim Ulang** insert a **new item** (kind `resend`) for the same
  visit revision — the old item's history is never reopened.

## 5. Reconciliation (r1 P1-3)
- **Uncertain create**: before any new create of a link that is `outcome_unknown`, search with the documented parameters (Q-19): Encounter `?subject=<ihs>`;
  Condition / Observation / Procedure / MedicationRequest `?encounter=<remote encounter>` (Condition also `?subject`); MedicationDispense
  `?subject&context`; Medication has no search (GET by id only) → a lost Medication create is never re-created automatically.
  Match only on the **exact stable identifier** (system + value, §2) — never on code or date.
- Exactly one match → `confirmed` with that id. Several → `exception: duplicate_remote`. A bundle that is incomplete (total > entries, or a
  next link) → treated as unresolved. **Zero → not recreated at once**: searched again after ≥ 30 min (a create may still commit late); zero
  twice → `exception: reconcile_unresolved` (manual; Kirim Ulang by a records officer or facility head creates anew, audited with reason).
- **Uncertain update (r2 P1-2)**: identifier equality never confirms an update. The worker reads the resource (`GET <type>/:id`, "Detail
  Data", documented for all seven types — Q-19 row "Read by id"; a failed read leaves the link a blocking exception) and compares the **fingerprint of the mapped fields** with the pinned revision's (§2): equal → `confirmed` at that revision; equal to
  the previous revision → checked again after ≥ 30 min (a late commit may still land); still not the intended content → `exception:
  update_unresolved` (blocking, §3). Medication (no search) follows the same read-by-id rule for updates.
